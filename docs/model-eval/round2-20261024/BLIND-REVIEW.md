## 5. 与模型无关、需要修的仓库问题

1. **英文模板里的劫财还是「Rob Wealth」**:`backend/app/ai/prompts/en/m0_structure_v11.md` 等模板把 Rob Wealth 写成规范术语,所有英文版本都照用。但 2026-09-29 已拍板改为「Wealth Rival」,`term_translations.py` 也已经改了。现在 iOS 界面显示 Wealth Rival,AI 正文却写 Rob Wealth,用户会看到同一个概念两种叫法。改模板会触发 prompt 守护栏:bump 版本号、三语同步、跑 evalkit。
2. **L2 判据缺「藏干归属」校验**:本轮最常见的硬伤是「X 支藏 Y 干为 Z 神」写错(把戊算成劫财、把巳中庚算成食神、把午中己算成正财、说辰里有印……),evalkit 一条都没抓到。这类错误可以完全确定性地检查:引擎已有每柱藏干和十神表,正则抽出「某支藏某干/某神」与表比对即可,成本低、零误报。建议加一条 L2。
3. **「并列最重」也可以确定性校验**:权重不相等却写「并列最重」,出现了 8 次以上。
4. **照抄示例和字段名外泄仍然存在**:「能跑的版本」「路线和餐厅」照抄示例;start_age、stem、branch、useful_god_candidates 等机器字段名出现在正文里。前者已有 L2 判据,后者需要补。
5. **M1 结构残缺没被 L1 拦住**:有些版本 defensive 条目缺 name 字段,有的 JSON 出现空键名,有的 trained/defensive 只给 1 条。建议 L1 加上「条目数下限 + 必填字段」校验。
6. **REPORT 自身有一处前后矛盾**:§3 说简体盲评包含 Gemini,§4-7 却写「Gemini 不进盲评包」。按包里简体是 5 个版本来看,§3 是对的,§4-7 应该改。
7. **盲评包与原始 run 同批推送**(见第 0 节):以后建议分两次推。
