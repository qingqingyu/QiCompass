## 0. 一句话

生肖反馈屏在属相层之上补一句**只属于本人的确定性过去节点句**(如「2016 年,流年冲你日支——命理中标记个人变动的一年」),后端规则引擎纯函数计算,iOS 静态三语模板渲染,**零 LLM、零交互、零持久化**。

## 2. 引擎规则细则(backend)

### 2.1 候选生成

对 `[birth_year + 16, 上一个完整公历年]` 内每个年份 Y:

1. `year_gz = year_pillar_ganzhi(Y)`(立春切换,泛化 `compatibility.py::_build_year_pillar_for_future`,见 §2.5)
2. 按序检测,同一年只记最强一档:
   - **rank 0 `chong_day_pillar`**:流年干五行克日干(任一方向)且 流年支与日支六冲(`LIUCHONG`)
   - **rank 1 `chong_day_zhi`**:流年支与日支六冲(未达 rank 0 时)
   - **rank 2 `chong_month_zhi`**:流年支与月支六冲
   - **rank 3 `luck_transition`**:Y ∈ `luck_pillars[*].start_year`
3. 同一年 rank 2/3 可并存(如冲月支年恰逢换运),取更小 rank

### 2.2 排除窗(D2/D4)

- `age = Y - birth_year`(整数差,展示文案加「约」软化立春节点误差)
- 排除:`age ∈ {17,18,19,21,22,23}` 或 `Y ∈ {2020,2021,2022}`
- 排除后空池 → 返回 None(**不放宽**——诚实优于硬猜)

### 2.3 选择

`(rank asc, Y desc)` 排序取第一个 → 同强度取离现在最近的(记忆最新鲜)。

### 2.4 输出 schema

```json
"past_node": { "kind": "chong_day_pillar|chong_day_zhi|chong_month_zhi|luck_transition",
               "year": 2016, "age": 26 }
```

- 后端只出结构化数据,不下文案(文案三语在 iOS xcstrings,与排盘响应语言无关的架构一致)
- `past_node: null` = 空池/降级/歧义,统一语义

### 2.5 复用与新增

- 新建 `backend/app/engine/verification.py`(纯函数 `pick_past_node`),天干相克复用 `pillars.WO_KE`(有向表,任一方向判定;单一事实源,不自含副本)
- `LIUCHONG` 复用 `branch_relations.py`
- `_build_year_pillar_for_future` 泛化改名为 `year_pillar_ganzhi(year: int)`(支持任意年份,逻辑不变:`Solar(year,2,4,12,0,0).getLunar().getYearInGanZhiByLiChun()`),移到 `pillars.py`,`compatibility.py` 改引用并删本地副本(**不复制粘贴**)
- 大运交接年取 `luck.py` 产出的 `start_year`(绝对公历年)

### 2.6 确定性口径

同一 birth 输入 + 同一查询时刻 → 同一输出。时间窗终点(上一完整年)随现实时间推进属**设计内时变**:老快照不存此字段、屏是 oneshot,无陈旧问题;新年份完整后重排盘自然纳入新候选。

## 3. API 契约

- `BaziResponse` 加 `past_node: PastNode | None = None`(Pydantic model `PastNode{kind, year, age}`)
- iOS `BaziDTOs.swift` 加 `pastNode: PastNodeDTO?`(`decodeIfPresent`,跟随现有 snake→camel 解码约定,同 `yearBranchFriends`)
- 老客户端忽略新字段/新客户端遇老响应缺字段 → nil,双向兼容,无迁移

## 4. iOS 落地

- `OnboardingView`:`personalTeaseText(from:)` → `nodeSentenceText(from:)`,读 `response.pastNode` → 按 kind 取 xcstrings 模板 + year/age 插值
- `ZodiacRevealView`:参数 `personalTease: String?` 更名 `nodeSentence: String?`,nil 不渲染;样式 **body 13 inkMuted 居中**(中文 UI=QiSongti,非中文按 `BaziFont.body` 既有回退=系统 13)——slot 与排版手法不变,字号/字体升半档
- 不新建 .swift 文件(避免 pbxproj 4 处登记),模板函数进 `ZodiacHelper`
- EN 长句走查:同 slot 手法(multilineTextAlignment + fixedSize),SE 级宽度不破版

## 5. 三语文案全文(**待拍板**)

| kind | zh | zh-Hant | en |
|------|----|---------|-----|
| chong_day_pillar | {year} 年(约 {age} 岁),流年与你的日柱天克地冲——命局中最少见的变化之年。 | {year} 年(約 {age} 歲),流年與你的日柱天剋地沖——命局中最少見的變化之年。 | In {year} (around age {age}), the year clashed with and opposed your day pillar — the rarest marker of change in a bazi chart. |
| chong_day_zhi | {year} 年(约 {age} 岁),流年冲你的日支——命理中标记个人变动的一年。 | {year} 年(約 {age} 歲),流年沖你的日支——命理中標記個人變動的一年。 | In {year} (around age {age}), the year's branch clashed with your day branch — a year bazi marks for personal change. |
| chong_month_zhi | {year} 年(约 {age} 岁),流年冲你的月支——命理中环境与根基变动的一年。 | {year} 年(約 {age} 歲),流年沖你的月支——命理中環境與根基變動的一年。 | In {year} (around age {age}), the year's branch clashed with your month branch — a year of shifting ground in your chart. |

- 用字对齐:zh-Hant 六冲=**沖**、克=**剋**(对齐 10-06 冲 chip 释义卡 xcstrings 衝→沖 的既有校正)

- xcstrings 4 key × 3 语,三语必须同批齐全(单语缺失 = 设备回落裸 key,既有坑)

## 6. 验收标准

1. 同一 birth + 同一时刻重排盘 → `past_node` 逐字节一致(纯函数,无 LLM/随机)
2. 排除窗/时间窗/空池/降级全部有测试枚举(§7)
3. iOS:有 node 渲染一句、nil 不渲染行、立春降级态整屏本就不出现该区、老响应不渲染
4. 三语 4 key 齐全(轻量 XCTest 断言三语非缺失,防裸 key)
5. EN 句在 SE 宽度不破版(渲染测试)
6. 全量测试绿(backend pytest + iOS xcodebuild)
