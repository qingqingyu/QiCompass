## 0. 背景(为什么要改)

v9 全量 run(`20261014T003509-0ad3ce`)里 20 张盘的 M0 有:

- **7 张在展开层写了干支**(leak 的大运句「戊寅 / 壬午 / 庚寅…」,body 的「乙木」)。plan 记录写「三轮加压不收敛」,于是决定不改模板,交给 evalkit 兜底。
- **问题**:evalkit 是离线回归工具,生产环境没有拦截。也就是说,约三分之一的真实用户会读到违反 v9 规则的内容。
- **用户拍板**:不再跟模型对着干。允许大运写成「约 X 岁起的那十年(某某运)」,干支只能放在这个括注里,而且必须和输入大运对得上。

另外,review 用探针确认了 v9 新加的两项 evalkit 检查会大量误报(见第 2 节 S2),必须先修好,再重跑全量、重设基线。

改动点(以 zh v9 行号为参照,zh-hant / en 按同语义改,不要机翻):

1. **【三层写法】第 4 条「大运写法」重写**(zh v9 第 76-78 行):
   - 展开层提到大运,统一写成「约 X 岁起的那十年(某某运)」。X 必须是输入大运里那一步的 `start_age`,括号里必须是同一步的干支,两者要对得上。

     - ✗「到了某某运,你会……」(没有年龄短语)
     - ✓「约 X 岁起的那十年(某某运),……」
   - 示例里只能用「X」和「某某」做占位,**不得**写真实干支或真实岁数,防止被照抄。
2. **同步改其他提到这条规则的地方**,不能留下互相矛盾的旧说法:

### S2 · evalkit 判据误报修复

#### S2-1 干支检查改为「接地匹配」(修误报 + 支持括注)

现状:`_GANZHI_CITE_RE`(第 793 行)匹配任意「天干 + 地支 / 五行」或「地支 + 五行」,被 `check_headline_plain_language`(第 861 行)和 `check_expansion_no_figures`(第 904 行)共用。下面 5 句日常中文全部被误报(review 实测):

| 句子 | 误判成 |
|---|---|
| 你自己未必意识到这一点 | 己未 |
| 你会先提升自己水平再出手 | 己水 |
| 你很少在自己金钱上算计 | 己金 |
| 你对自己土气的一面并不在意 | 己土 |
| 作品一下子火了以后你反而退后 | 子火 |

改法:

1. **从引擎结果构造本盘「可引用干支集」**:
   - 干支对:`engine_result["pillars"]` 四柱的 `gan_zhi`、`engine_result["luck_pillars"]` 每步的 `gan_zhi`
   - 「干 + 五行」「支 + 五行」注记:只收**本身五行正确**的组合(如庚金、壬水、午火、戌土),字取自上述干支
   - 不要手写死清单
2. **只匹配可引用集合里的形态**。「自己水平」里的「己水」五行不对(己属土),天然不会命中。
3. **「自己」豁免**:匹配以「己」开头且前一个字是「自」时跳过(覆盖本盘带己、出现「自己土气 / 自己未必」的情况)。
4. **括注豁免(只对展开层)**:形如「约 N 岁起的那十年(XX运)」的括注里的干支不算违规,但要做**岁数对账**:
   - XX 必须是 `luck_pillars` 里存在的干支,且该步 `start_age == N` → 放行
   - XX 不在 `luck_pillars` 里 → fail「编造大运干支」
   - XX 存在但 `start_age != N` → fail「大运岁数与干支对不上」
   - 括号兼容半角和全角;年龄短语里的数字照旧由 `_AGE_RE` 豁免
5. **结论层不享受括注豁免**:headline / name 出现任何可引用干支都 fail(行为不变,只是换成接地匹配)。
6. 已知漏报(接受,写进 docstring):盘里不存在的干支(纯编造)在括注以外不会被这项检查抓到,本轮不处理,见 S4。

必须有的单测:
- 反例(不得报):上表 5 句日常中文;另取一张大运或四柱里带「己」的盘,验证「自己土气」不报
- 正例(必须报):展开层出现本盘干支「庚午」;展开层出现「壬水」(本盘有壬);结论层出现「约 X 岁起的那十年(XX运)」
- 括注三态(用样本盘真实大运:壬寅 5 岁、癸卯 15 岁、甲辰 25 岁…):
  - 「约 25 岁起的那十年(甲辰运)」→ 放行
  - 「约 15 岁起的那十年(甲辰运)」→ fail,岁数对不上
  - 「约 25 岁起的那十年(庚子运)」→ fail,编造大运
  - 全角括号写法同样要测

#### S2-2 「权重 >0 不得写缺」去掉「没有」

现状:`_MISSING_WORDS`(第 915 行)含「没有」,下面 3 句全被误报(review 实测):

- 正财没有七杀那么重(比较句)
- 七杀压力没有压垮你(否定的是后面的动词)
- 伤官的锋芒没有用上(藏而不用,不是缺)

改法:从 `_MISSING_WORDS` 删掉「没有」,只保留「缺位 / 缺失 / 不存在」;删除专为「没有透出 / 没有露出」写的守卫分支;docstring 写明理由(「没有」在中文里多为比较或否定动词,宁可漏报)。上面 3 句作为反例单测。真机正例「官杀系统整体缺位」必须仍然能抓到。
