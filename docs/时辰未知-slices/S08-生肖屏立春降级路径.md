# S08 生肖屏立春降级路径

- **类型**: AFK
- **Blocked by**: S02(年柱歧义标记契约)、S04(onboarding 无时辰链路)
- **覆盖决策**: D10 命中后果(年柱歧义→生肖不可用,生肖屏降级不猜)/ D7(明确不在生肖屏放常规补时辰触点——降级态例外,是被迫告知)
- **Parent**: `docs/时辰未知设计决策.md`

## What to build

onboarding 第 3 屏(ZodiacRevealView,产品第一个「哇」时刻)对立春日 + 无时辰用户的降级:

1. **判据**:`year_branch_zodiac=null`(S02 立春歧义)→ ZodiacRevealView 切降级态:
   - 不展示生肖/好朋友/需磨合(这些都从年支出)
   - 文案:如实告知「你的出生日在立春交界,需要准确时辰才能确定属相」——**不猜**、不展示任一侧候选生肖
   - 给补时辰入口占位(一期轻提示,S10 接线);CTA「继续」保留(完成 onboarding 进 App,四柱页留白表达)
2. **正常路径零变化**:非立春日(含无时辰但年柱确定的 ≈99.7% 用户)生肖屏照常——无时辰用户的生肖反馈是 onboarding 里少数**完全不受影响**的奖励,保持「哇」时刻
3. **Profile 命主卡 / 生肖头像**:`year_branch_zodiac=null` 的展示(08-15 登录态生肖头像)→ 留白或通用墨点表达,不 crash 不猜

## Acceptance criteria

- [ ] 立春日 + hour_known=false 响应(zodiac=null)→ 生肖屏降级态:无生肖内容、有告知句、可继续完成 onboarding
- [ ] 普通日 + hour_known=false → 生肖屏与现状一致(生肖/好朋友/需磨合照常)
- [ ] 有时辰用户(含立春日,时辰可判侧)→ 完全现状行为
- [ ] 降级态完成 onboarding → `hasSeenOnboarding` 状态边界照常(Q7,不因降级态重复触发)
- [ ] Profile 生肖相关展示对 zodiac=null 不 crash、不猜
- [ ] XCTest:降级/正常/有时辰三分支 + 状态边界

## 实现锚点(现状快照 2026-08-31,实施以代码为准)

- `iOS/QiCompass/QiCompass/Features/Onboarding/ZodiacRevealView.swift` — 生肖反馈终态屏
- `iOS/QiCompass/QiCompass/Features/Onboarding/OnboardingView.swift:101-123` — `.ready` 分支 + onComplete/hasTriggeredComplete 状态边界
- `iOS/QiCompass/QiCompass/Shared/ZodiacHelper.swift` — 生肖映射(null 输入的处理点)
- `iOS/QiCompass/QiCompass/Features/Profile/ProfileView.swift` — 命主卡/生肖头像消费点

## 红线与约束

- 不猜:两侧候选生肖都不展示(「可能是龙也可能是蛇」这种表达禁止)
- 降级文案克制:水墨语言,一句告知 + 一个动作,不做长解释
- 新文案进 L10n(中英)
- 不动后端(契约 S02 已定)
