# S02 D10 节气边界双排盘比对

- **类型**: AFK
- **Blocked by**: S01(在 hour_known=false 路径之上)
- **覆盖决策**: D10(节气边界双排盘)/ 依赖表「节气边界依赖」行(立春→年柱+生肖;节交界→月柱→调候+得令+大运序列)
- **Parent**: `docs/时辰未知设计决策.md`

## What to build

`hour_known=false` 时,年/月柱在节气交界日并非确定。检测与降级:

1. **双排盘比对**:对该出生日(12:00 占位同款时区/真太阳时链路)的 00:00 与 23:59 各排一次,比对**年柱与月柱**干支——不一致的柱标 unknown(日柱歧义已由 S01 late_night 处理,不重复)
2. **响应标记**:歧义标记字段(如 `pillar_ambiguity: {year: bool, month: bool}` 或等价显式表达),进响应 + `calc_rule_snapshot` + content_hash(S01 已留「歧义标记参与 hash」位)
3. **命中后果级联**:
   - 月柱歧义 → 调候(查月支)与得令(`DELING_WEIGHT=5`)不可用 → strength 维持 `unknown_hour` 语义(本就不可用,但月柱歧义时连三柱叙事的月柱部分也要置空)、**大运干支序列置 unknown**(大运从月柱起排)
   - 年柱歧义(立春日)→ 年柱置 unknown + **生肖置 null**(`year_branch_zodiac=null`),供 S08 生肖屏降级
4. **确定性**:同输入同输出;比对用 lunar_python 节气表(精确到分),不自算节气

不命中(≈96% 用户)→ 零歧义标记,响应与 S01 基础态一致。

## Acceptance criteria

- [ ] 立春日当天出生 + `hour_known=false` → 年柱 unknown + `year_branch_zodiac=null` + 歧义标记
- [ ] 任一节交界日(12 节/年)出生 + `hour_known=false` → 月柱 unknown + 大运序列置 unknown + 歧义标记
- [ ] 普通日子出生 + `hour_known=false` → 无歧义标记,年月柱照常(与 S01 输出一致)
- [ ] `hour_known=true` → 永不触发比对(老路径零开销)
- [ ] 歧义标记参与 content_hash:同日有/无歧义 → 不同 hash;歧义状态进 calc_rule_snapshot
- [ ] pytest:立春/节交界/普通日三组用例,含回归佐证(参考现有 `tests/test_bazi_calculate.py` 立春用例附近)
- [ ] 生肖 null 的响应字段 iOS 侧可解码(S05/S08 消费,本 slice 只保证契约)

## 红线与约束

- 不猜:歧义柱显式 unknown,禁止取 00:00 侧或 23:59 侧任一结果
- `hour_known=true` 路径零改动(性能与行为)
- 双排盘只在无时辰时发生,单次请求成本可接受(两次 CPU-bound 排盘,已有 threadpool 包装)
