# 「不知道出生时刻」全链路设计决策

## 背景

排盘准确性是产品命根。当前 onboarding 出生表单(`BirthFormView`)存在两个同源的数据质量洞:

1. **无「时辰未知」入口**:不知道出生时刻的用户,表单里只有躺着的默认时刻,没有任何显式承认「我不知道」的路径。用户只能(а)不碰表单用默认值,或(b)用「时辰快捷选」挑一个貌似接近的——两种都以**无痕迹的假精度**建档,后端永远收到一个看起来精确的 `HH:mm:ss`。
2. **默认日期洞**:`DeepAnalysisViewModel.birthDate` 默认 1990-03-15,校验只有「不晚于当下 + 选了城市」两条(`DeepAnalysisViewModel.swift:152`),日期字段可以完全不触碰就提交,现在只靠二次确认 sheet 兜底。

时柱的牵连面(backend 实测,决定一切后续设计):

| 依赖级别 | 内容 | 代码位置 |
|---|---|---|
| **强依赖** | 时柱本身 / 五行统计 / **日主强度→喜忌引擎** / 十神权重 / 20 个神煞 / 每日运势 12 时辰柱 | `pillars.py:127` / `xiji.py:126` / `shensha.py:33` |
| **完全不依赖** | 生肖(年支) / 年月日柱 / **大运起排**(只要日期+性别) / 流日流年 | `bazi_engine.py:94` / `luck.py:10` |
| **边界歧义** | setSect(1) 23:00 换日 → 「深夜」出生者**连日柱都有歧义窗**(23:00-23:59 归次日) | 全局子时规则 |
| **契约** | content_hash 含 2 小时时辰桶 | `content_hash.py:27` |

**关键级联**:喜忌是深度解析/合盘/每日运势三大 AI 模块 prompt 上下文的根基。没时辰 ≠ 少展示一柱,而是三大模块失去核心依据。

## 决策汇总

| # | 决策点 | 结论 |
|---|---|---|
| D1 | 入口结构 | **单一入口,系统分流**:表单加「不知道出生时刻」选项,不让用户做「猜时刻 vs 接受不准」的元选择 |
| D2 | 人格题反推 | **砍掉** |
| D3 | 时段线索 | **收集四段(可选)**,只用于日柱歧义判断 + 存档;不反推、不影响喜忌 |
| D4 | 喜忌引擎 | 时辰未知 → `day_master_strength="unknown_hour"`、喜忌留空,**复用从格 special_pattern 诚实降级先例** |
| D5 | 三模块策略 | 每日运势(免费)**降级提供**;深度解析+合盘(付费)**拦截** |
| D6 | 付费边界 | **拦购买动作**(模块入口处,早于付费墙);**redeem 不拦**(权益记账照常,内容拦) |
| D7 | 补时辰入口 | Profile 命主卡常驻「补充出生时刻」(只补时辰)+ 拦截页 CTA 直跳 |
| D8 | 默认日期洞 | **一起修**:日期必选,未触碰不能提交 |
| D9 | 实施节奏 | **两期**:一期数据质量,二期降级体验 |

## D1 单一入口,系统分流

表单加显式「不知道出生时刻」选项(checkbox 或 chip)。选中后时刻输入收起,系统统一进入降级流程。

否决「用户自选两条路」(不知道时辰后让用户选「猜个大概」或「接受不准看三柱」):
- 用户不该被问「你要哪种质量的数据」这种元问题——数据质量责任在产品,不在用户
- 与「专业不忽悠」一致:产品替用户做诚实选择

否决「两步串联」(先问时段,给了走模糊时柱,没给降级):时段给出的仍是 2-3 个候选时辰,后续处理复杂且引向 D2 已砍掉的反推。

## D2 砍掉人格题反推(用户原始方案一的部件)

用户最初设想:选完时段后「问几个个性问题,看哪个(时辰)符合他,按这个来」。**砍掉**,理由:

1. 用性格问卷「算出」出生时辰是典型算命软件套路,与 Memorable Thing「专业不忽悠」直接冲突
2. 猜错时柱 → 喜忌错 → 三大模块全错,**且用户不知道是猜的**——错误代价被完全隐藏
3. 反推映射表本身无从验证,违背「确定性判断不交给玄学」的 LLM 边界原则

「问几个问题看个性」若未来要做,只能作为生肖屏/Profile 的娱乐内容(类似星座趣味),永不参与排盘。

## D3 四段时段线索:收集,但只做两件事

「不知道出生时刻」后问一句四段时段:**上午 / 下午 / 傍晚 / 深夜**(可不选)。

v1 用途仅两个:
1. **日柱歧义判断**:上午/下午/傍晚 → 日柱可靠;深夜 → 日柱踩进 23:00-24:00 歧义窗,日柱也标未知。这是时段线索唯一的计算用途
2. **存档元数据**:ChartSnapshot payload 存 `time_segment`,供未来「候选时辰共识盘」(按时段内候选时辰逐个排盘,只展示一致部分)——本期不做

明确不做:不用时段反推具体时辰、不用时段中点假装时柱。

否决「不收集直接降级」:深夜用户的日柱歧义无法识别,且未来共识盘没数据。
否决「v1 就做共识盘」:后端排盘/喜忌/缓存全部要支持多候选语义,工作量最大,YAGNI。

## D4 喜忌引擎:输出「不可用」,复用从格先例

时辰未知时后端喜忌引擎(扶抑+调候+从格)**不硬算**:

- `day_master_strength="unknown_hour"`,favorable/unfavorable 留空
- LLM 拿到该状态后诚实告知「时辰未知,喜忌分析需要准确时辰」

这与架构里已有的从格检测 D3 先例完全同构(命中 → `special_pattern` → 喜忌留空 → LLM 诚实降级),零新范式。

否决「引擎改支持 6 字计算」(分母 8→6):权重公式按 8 字校准,改分母后数值意义变了;从格 6/8 阈值缩到 6 字后误判率未知;喜忌是三模块根基,可靠性无法验证。

否决「排盘直接拒绝无时辰请求」:连生肖/三柱/大运这些可靠结果也一并拒绝,与「能给的诚实给」相悖。

附:神煞按三柱查(时支神煞自然缺失),输出标注「可能不全」;大运、生肖、流日流年照常。

## D5 三模块:免费降级提供,付费拦截

| 模块 | 定位 | 无时辰策略 |
|---|---|---|
| 每日运势 | 免费(B2 入口) | **降级提供**:prompt 走「日柱×流日十神关系」叙事(不依赖时柱的部分),明示局限 |
| 深度解析 | 付费 | **拦截**,拦截页引导补时辰 |
| 合盘 | 付费 | **拦截**(对方无时辰只拦该对,复用 D13 对级错误隔离) |

理由:
- 免费入口模块没了,无时辰用户几乎无留存理由;每日运势用不依赖时柱的部分仍有依据可讲
- 付费模块卖「引擎明确告知喜忌不可用」的解读 = 卖残次品,伤信任 + 退款风险
- 拦截页本质是「补时辰解锁」转化钩子,不是死胡同(见 D7)

代价(二期实施):每日运势 prompt 要支持喜忌缺失分支 → `REQUIRED_FIELDS` 三边同步 + evalkit 跑一轮(CLAUDE.md 双护栏)。

## D6 付费边界:拦购买,不拦 redeem

- **拦购买**:拦截点在模块入口(比付费墙更早)——无时辰用户看到「补充出生时刻后解锁」页,**不展示价格、不触发 purchase**。避免最危险序列:先付钱 → 再发现没内容 → 退款 + 差评
- **redeem 不拦**:兑换码照常可兑,entitlement 正常记账(绑 user),内容仍拦截;补完时辰后 hash 重建、权益自动生效。礼物不丢,立场不破。代价:redeem 成功后接一个「补时辰后可用」引导页

否决「redeem 也一刀切」:礼物码场景体验最差(别人的礼物兑不了),活动码投放前还要先筛用户状态。
否决「redeem 时引导先补时辰再继续兑换」:redeem 流程里嵌表单,交互链与测试面最大。

## D7 补时辰:Profile 常驻入口 + 拦截页直跳

- Profile 命主卡加常驻「补充出生时刻」入口,**只补时辰一个字段**(不重填姓名/性别/地点);付费拦截页 CTA 直跳同一入口
- 补后 content_hash 变(2h 时辰桶参与计算)→ 视为新命盘,老三柱盘归档保留
- 缓存按新 hash 自然重建、付费 entitlement 若绑 hash 需同步迁移(内容寻址设计的红利)
- 现状「只能重置命盘重走全部表单」保留给改日期/性别/地点场景(对齐生肖决策 Q20)

## D8 默认日期洞一起修

出生日期改「未选择」初始态,必须触碰 DatePicker 选过才能提交;配合时辰未知 flag,表单状态机一次改到位。`birthDate` 变 Optional,绑定/二次确认 sheet/测试链路同步小改。

## D9 两期实施

**一期(数据质量,iOS + 后端最小改动)**:
- iOS:表单「不知道出生时刻」入口 + 日期必选 + 四段时段(可选)
- 后端:`hour_known` 契约 + 喜忌 unknown_hour + 三柱排盘(含深夜日柱歧义)
- 三模块**临时全拦截**(拦截页一句话 + 补时辰入口占位)
- 生肖反馈屏(第 3 屏)只依赖年柱,不动

**二期(降级体验)**:
- 每日运势降级版 prompt(REQUIRED_FIELDS 三边同步 + evalkit 无 regression)
- 付费拦截页文案/付费墙适配 + redeem「补时辰后可用」引导页
- 补时辰升级闭环(Profile 入口 + entitlement 迁移)
- 合盘对方无时辰的对级拦截

每期可独立验收。

## 契约与护栏备注

- `birth_datetime` 建议短格式 `yyyy-MM-dd` + `hour_known` bool flag,**flag 是唯一事实源**(不用 00:00:00 哨兵值伪装)
- 改 prompt 模板必须:三边同步校验(`tools/check_prompt_sync.py` PASS)+ evalkit 无 regression + bump `PROMPT_VERSIONS`(CLAUDE.md 双护栏)
- ChartSnapshot payload 加字段(hour_known/time_segment)必须 `decodeIfPresent`(2026-08-15 老盘 keyNotFound 教训)
- content_hash:`hour_known=false` 时以日期(深夜含歧义标记)参与,时辰桶不参与
