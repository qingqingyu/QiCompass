## 0. 目标

第一章(免费)的四个问题不变,改的是**每题的回答写法**:固定为三层。

1. **一句白话结论**(视觉突出,不出现十神名词、干支、数字)
2. **2–3 句展开**,十神名第一次出现时带白话释义,全章至少一个具体生活场景
3. **据 ›** 折叠:十神分层、权重、五行计数、干支、大运全放这里

### 0.1 目标样例(用户拍板的写法,验收锚点)

样本盘:丙寅 辛丑 庚午 庚辰(日主庚金偏旺,七杀 6 = 劫财 6 并列最重)。

> **1. 主线** — **压力推着你走,你靠「学规矩、攒资历」接住它。**
> 主导是七杀,也就是外部压力和硬要求;其次是正印,也就是体系、资质和靠山。藏着没发挥出来的,是表达力和赚钱能力。
>
> **2. 核心循环** — **扛压 → 沉淀 → 扛更大的压。**
> 每次被逼着解决难题,你都会把它变成一套方法或一份资历,这又让你接得住下一个更重的担子。
>
> **3. 结构类型** — **被逼出来的专业型。**
> 你的分量不是靠表现出彩,而是靠一件件扛下来的事攒出来的。
>
> **4. 能力来源** — **最强在「给你一个难题,并让你自己搭体系」的时候;最弱在要你公开展示、自己推销自己的时候。**
> (展开只讲优势从哪来,弱的原因在「核心循环」的代价段讲,不重复)
>
> *据 ›* 七杀与劫财并列最重;日主庚金偏旺……(全部命理依据)

注:用户最初的样例写的是「杀印相生格,白话说是…」。v7 已按 ADR-0006 禁止一切以「格」结尾的格局名(含复合格名),本 plan 维持该红线,样例里只保留白话名。

## 1. 现状核查(v7 重新生成后的真机截图)

样本盘:癸酉 乙卯 辛丑 戊戌(日主辛金;偏财 8 = 正印 8 并列,食神 6,比肩 5,七杀 1,正官 0)。

v7 已修掉的(不用再做):格名(输出「印财对峙、食伤通关型」,无「格」字、无括注)、并列最重分层正确、十神归属与藏干位置正确、翻译回译括注。

v7 之后**仍然存在**的问题,也就是本 plan 要解决的:

| # | 现象(截图原文) | 根因 |
|---|---|---|
| P1 | 每节第一眼都是术语:「主导 · 偏财与正印并列主导。偏财重 8,正印重 8,天干月令透偏财(乙卯)…」「起点 正印 终点 偏财」 | schema 没有「结论」字段;v7 把 dominant/secondary/latent 写成了**带权重的长句**,iOS 又把它们排在节首。数字和干支进了正文 |
| P2 | 结构名「印财对峙、食伤通关型」仍是术语(印、财、食伤、通关) | v7 只禁了「格」,没禁十神名及其简称 |
| P3 | 正文里没有任何十神白话释义,外行读不懂「比肩生食神、食神生偏财这一段」 | 只有 daily_fortune v4 有「术语首现附白话」规则,M0 没有 |
| P4 | 工程腔、翻译腔:「通道」「转换层」「输出链」「正印端不断供」「这一段」「咽喉」 | v7 只给了一组 ✗/✓ 示例,没有禁用词表 |
| P5 | 「先做出能跑的版本,再拿它去换空间」——**照抄**了共享 header 的 ✓ 示例句(「先做出一个能跑的版本」) | 提示词里的示例句没有「不得复用」约束,也没有机器检查 |
| P6 | 流向:「正印生比肩 → 比肩生食神 → 食神生偏财 → 偏财回克正印」三个箭头 | v7 规则④ 只靠 prompt,LLM 未遵守;evalkit A4 能拦但生产侧不拦(BASELINE 里也有 1 例) |
| P7 | 「七杀仅 1,藏于时支戌中不透…官杀系统整体缺位」——七杀权重 1(藏),却写成「缺位」 | 违反 v7 ⑥「缺/藏/弱」三分法,没有机器检查 |
| P8 | 结尾运转概括「吸收与抓取两端等重…输出一多吸收就被压缩」与损耗段「吸收和沉淀的通道就被压缩」重复 | structure_fingerprint 是给下游链式继承用的 40 字机器锚点,「不含形容词」读起来干;在 M0 章里展示等于再说一遍 |

#### 1.2 字段职责表(写进模板,替换 v7「字段职责」那一条)

| 字段 | 层 | 写什么 | 禁止 |
|---|---|---|---|
| `main_axis.headline` | 结论 | 一句话:是什么力量推着你走,≤25 字 | 十神名及简称、干支、数字 |
| `main_axis.body` | 展开 | 2–3 句:主导 / 次要 / 潜伏三股力量分别是什么,十神名首现带白话释义 | 数字、干支 |

| `capability_source.headline` | 结论 | 「最强在……;最弱在……」两个场景各一句,不讲原因(D2) | 十神名及简称、干支、数字 |

#### 1.3 新增规则块(放在【数据口径】之后、`{chart}` 之前)

1. **三层写法**:每节先写结论,再展开,依据只进「据」类字段(见上表)。结论句要让完全不懂命理的人一眼看懂。
2. **十神白话表**:十神名第一次出现在展开层时,紧跟白话释义,之后可以直接用名字。释义用下表,可以按本盘语境微调,但不得和表的意思矛盾:

   | 十神 | 白话 |
   |---|---|
   | 比肩 | 自己的主见、和你同路的伙伴 |
   | 劫财 | 同辈之间的竞争、和人抢资源 |
   | 食神 | 自然流露的产出、手艺和享受 |
   | 伤官 | 表达欲、挑战规矩的锋芒 |
   | 偏财 | 抓机会、调动资源的嗅觉 |
   | 正财 | 稳定收入、一点点攒下来的积累 |
   | 七杀 | 外部压力和硬要求 |
   | 正官 | 规则、职位和名分 |
   | 偏印 | 偏门的学识、一个人钻研 |
   | 正印 | 体系、资质和靠山 |

   en / zh-hant 版本的十神名用 `term_translations.py` 的现行译名,白话释义各自按母语写,不机翻。

3. **数字只进据**:展开层和结论层不得出现权重、五行计数等数字;唯一例外是「约 X 岁」这种年龄。
4. **大运写法**:展开层提到大运时写「约 X 岁起的那十年」(用输入大运的起运岁数),干支写进 evidence。这是对 v7 ⑦「引用大运实际干支」的改写:**依据仍然必须来自输入大运**,只是干支挪到据里。
5. **生活场景**:全章至少一个具体场景,要带上「什么时候、对谁、做什么」。
6. **不得复用示例**:本提示词里出现的任何示例句(包括上方共享部分的 ✓/✗ 示例、下方写法示范)只演示写法,内容一律不得照搬或改写使用。
7. **禁用词**(展开层与结论层):通道、链条、输出链、环节、转换层、「X 端」(输出端 / 吸收端 / 正印端)、「这一段 / 那一段」(指循环中的某段)、承载、权柄、泄漏、流失、巩固、咽喉、缺位、对峙、通关。想说这些意思时,改用可观察的行为来写。
8. **缺 / 藏 / 弱 再强调**(P7):权重 >0 的十神或十神类别,任何地方都不得写成「缺位 / 缺失 / 没有 / 不存在」。

#### 1.4 四个问题改写(替换 v7 的 1–4 问)

```
请从十神结构出发分析这个命局,不要讲吉凶和神煞。四节各答一件事,不互相重复:

1. 主线:是什么力量在推着你走?(main_axis:结论 + 展开三股力量 + 据里写十神分层)
2. 核心循环:这股力量怎么转起来,又在哪里付出代价?(core_loop:结论 + flow 讲怎么转 + leak 讲代价、变化条件与出路)
3. 结构类型:用一个白话名字给你定性。(structure_type:name 是结论,one_line 是展开)
4. 能力来源:你在什么场景最强、什么场景最弱?(capability_source:headline 两个场景各一句;text 只讲优势从哪来,弱的原因已在 leak 里讲过,不重复)
```

校验行同步改:加上「所有 headline 与 structure_type.name 不含十神名及简称、干支、数字」「展开层不含数字(年龄除外)」。

#### 1.5 写法示范(放进模板,和本盘无关)

用一个结构不同的虚构盘(伤官旺、生财,印弱)只示范 headline / 展开两层,evidence 写「(按证据引用纪律写依据)」占位,并在示范上方注明「仅示范写法,不得照搬任何句子」。参考稿(实施方可润色):

- 主线 · headline:「你靠说出来、做出来打开局面,钱跟着作品走。」
- 主线 · body:「主导是伤官,也就是表达欲和挑战规矩的锋芒;其次是正财,也就是稳定、一点点攒下来的收入。藏着没用上的是正印——系统学习、找靠山的能力。」
- 循环 · headline:「冒出想法 → 做成东西 → 换成收入 → 再冒新想法。」
- 循环 · leak:「代价是不爱打基础:做到七八成就想换方向,证书、资历这类要慢慢攒的东西总是欠着。约 X 岁起的那十年,坐下来系统学习会变得容易坚持;眼下可以给每件事定一个『做完才换』的节点。」
- 类型 · name:「想到就做的作品型」
- 能力 · headline:「最强在要你从零拿出方案的时候;最弱在要你照章办事、按部就班的时候。」
- 能力 · text:「比如朋友聚会还在群里争去哪,你已经把路线和餐厅排好发出来了——从零到一的时刻,你反应最快。」

示范里的独特短语(「想到就做的作品型」「做完才换」「路线和餐厅」「从零到一的时刻」)和共享 header 的 ✓ 示例(「能跑的版本」)一起登记进 S2 第 5 条的抄袭检测清单。

### S2 · evalkit 检查(必做)

改 `backend/evalkit/checks/grounding.py`,单测放 `backend/tests/test_evalkit_grounding.py`。沿用该文件「宁可漏报不可误报」立场,**只对 m0_structure 生效**(和 v7 批的五项一样)。正例 fixture 用 §1 截图原文和 §0.1 样例,另配日常用词反例。

1. **结论层无术语**:`main_axis.headline` / `core_loop.headline` / `capability_source.headline` / `structure_type.name` 不得含 §1.2 十神名及简称表、天干地支两字组合(天干 + 地支)、阿拉伯数字。headline 缺失或非字符串 → fail。正例:「印财对峙、食伤通关型」。单字简称只在 `structure_type.name` 里判(其他 headline 里「财」等单字可能是正常用词,宁可漏报)。
2. **展开层无数字**:`main_axis.body` / `core_loop.flow` / `core_loop.leak` / `structure_type.one_line` / `capability_source.text` 不得出现阿拉伯数字,`\d+\s*岁` 豁免。正例:「偏财重 8」。
3. **权重 >0 不得写缺**(P7):同一句里(按 `。;!?` 切句,复用现有 `_SENTENCE_SPLIT`),十神名或十神类别后 6 字内出现「缺位 / 缺失 / 没有 / 不存在」,而该十神(类别取类内权重之和)权重 >0 → fail。正例:「官杀系统整体缺位」(七杀 1)。反例:「正官为 0」(正官权重 0)。
4. **禁用词**:§1.3 第 7 条词表命中展开层或结论层 → **只提示不判 fail**(词表会误伤,先观察分布)。注意:现有 warn 档来自 L3 裁判分数(`evalkit/store.py`),L2 grounding 检查接口只返回 failures 列表;实施方先确认能否在 L2 出 warn,不能就做成 run 报告里的统计项,不进 failures。
