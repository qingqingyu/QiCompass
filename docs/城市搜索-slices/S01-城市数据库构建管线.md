# S01 城市数据库构建管线(cities.sqlite + manifest + 守护栏)

- **类型**: AFK(带停止条件:实测体积 >25MB 或数据异常 → 停下报告,等用户拍板切 cities5000)
- **Blocked by**: None — 可立即开始
- **覆盖决策**: Q2(数据源/构建管线/不用 FTS/CC-BY)/ Q3(粒度/区县别名)/ Q6(归一化/索引形态)/ Q7(双列命名/CLDR/admin1 兜底)/ Q9(单一事实源/check 守护栏/体积门槛)
- **Parent**: `docs/城市搜索设计决策.md`

## What to build

`tools/build_city_db.py`:从 GeoNames 原始 dump 一步生成 iOS 离线城市库 + 清单,配套 `tools/check_city_db.py` 守护栏。产出物:

1. **`ios/QiCompass/QiCompass/Resources/cities.sqlite`**(路径实施时可调),schema 建议:
   - `cities(geoname_id INTEGER PK, name TEXT, name_zh TEXT, name_en TEXT, country_code TEXT, admin1_code TEXT, admin1_name TEXT, lat INTEGER, lon INTEGER, tz_id INTEGER, population INTEGER)`——经纬度存定点整数(原值×10^4),时区字符串换 FK 进 `timezones(tz_id, iana_name)`(~450 行)
   - `search_keys(key TEXT, geoname_id INTEGER, key_type TEXT)`——每城展开:简体名、繁体名、英文名、全拼、拼音首字母、别名;key 全部过**归一化**(NFC + 大小写折叠 + 变音符折叠 ü→u/é→e)
   - `name_zh` 取 GeoNames zh alternate,缺失 fallback `name`;admin1 中文名能提多少提多少,缺失英文兜底
2. **`manifest.json`**(进 git):条目数 / 数据集(cities1000)/ GeoNames dump 日期 / sqlite 内容 hash / 构建参数
3. **`tools/city-data/curated_aliases.tsv`**(进 git):人工精选别名 + 重点城市区县别名种子(三藩市→San Francisco、雪梨→Sydney、海淀→北京、浦东→上海、虹桥→上海 等,首批 ≥30 条)
4. 拼音:`pypinyin`(构建期,已批准)从汉字生成全拼+首字母;GeoNames `ascii_name` 拼音作交叉校验
5. **GeoNames 原始 dump 不进 git**:脚本按需下载(幂等,断点复用本地缓存),可 `--dataset=cities5000` 切换(同 schema 同管线)

`tools/check_city_db.py` 守护栏:表结构断言 + manifest hash 与 sqlite 实际 hash 一致 + 关键城市抽查(北京 lon≈116.41/tz=Asia/Shanghai;洛杉矶 ≈-118.24/America/Los_Angeles;伦敦 ≈-0.13/Europe/London;悉尼 ≈151.21/Australia/Sydney)+ 抽查搜索键(「乌木」「wulumuqi」「wlmq」「三藩市」均能命中乌鲁木齐/旧金山)。**动了 build 脚本或 sqlite 必须跑且 PASS**(写进两脚本 docstring)。

## Acceptance criteria

- [ ] `python3 tools/build_city_db.py` 幂等:重跑产出 byte-identical 的 sqlite + manifest(确定性红线)
- [ ] cities1000 全量入库(≈14 万条),直辖市/地级市/县级市可查(昆山、义乌在内)
- [ ] 海外城市可查:Berkeley、Cambridge(英/美两条都在)、Corvallis、Schenectady
- [ ] 搜索键覆盖抽查通过:乌木/wulumuqi/wlmq→乌鲁木齐;三藩市→旧金山;臺北→台北;munchen→München;海淀→北京
- [ ] 双列命名:name_zh 有值时为中文(旧金山),缺失时 = name 原文(Corvallis)
- [ ] 国家中文名来自 CLDR(~250 国),admin1 中文名缺失时英文兜底
- [ ] sqlite 体积**实测并写进交付报告**;≤25MB → 保持 cities1000 收工;>25MB → 停止,输出 cities5000 对比数据等用户拍板
- [ ] `python3 tools/check_city_db.py` PASS(结构/hash/抽查全绿),失败场景(改坏 sqlite)能抓出来
- [ ] 原始 dump 不进 git;curated_aliases.tsv 与 manifest.json 进 git
- [ ] 构建报告附:体积、条目数、时区表条数、别名种子数、构建耗时

## 红线与约束

- **确定性**:同一 dump 日期 + 同一脚本 → byte-identical 产出(排序稳定、无时间戳混入)
- **不擅自加依赖**:`pypinyin` 仅构建期(已批准);**运行时零新库**——sqlite 由 iOS 系统 SQLite 读
- **不用 FTS**:keys 表 + LIKE 方案,本 slice 只产数据,查询逻辑在 S03
- **错误显式传播**:dump 下载失败/字段缺失/别名冲突解析失败 → 报错退出,不静默跳过;统计性 warning 可有,数据丢失不可有
