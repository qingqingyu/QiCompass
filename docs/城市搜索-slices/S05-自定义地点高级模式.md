# S05 自定义地点高级模式(经度 + IANA 时区必填)

- **类型**: AFK
- **Blocked by**: S03(可与 S04 并行)
- **覆盖决策**: Q8(自定义地点/时区必填/Etc-GMT-X 兜底/4 位小数精度)
- **Parent**: `docs/城市搜索设计决策.md`

## What to build

用「自定义地点」高级模式替换旧「手动输入经度」开关,修掉该路径的结构性残缺(旧开关只填经度、钟面仍按设备时区解释 → 海外手动用户时辰照错):

1. **入口收进 `CitySearchSheet` 内**:列表底部一行「找不到出生地?自定义地点」——所有入口(深度解析/合盘/onboarding)自动继承,不只在 BirthFormView
2. **表单**:
   - 经度输入(东正西负,[-180,180] 校验,4 位小数精度提示)
   - **IANA 时区必填选择**:常用列表 ~40 条,带样例文案(GMT+8 · 中国标准时间 / GMT-8 · 太平洋时间 / GMT+9 · 日本标准时间 …)+ 末尾「固定偏移」组(`Etc/GMT-8` 等,注意 IANA `Etc/GMT-X` 符号与直觉相反:X 为正数表示东经——实现与文案都要核对这个坑);全部为合法 IANA 名,后端 zoneinfo 统一解释,历史夏令时对地区时区自动生效
   - 时区列表为静态常量(或从 cities.sqlite 时区表生成),不引新数据源
3. **选中态**:回显「自定义地点 · GMT+8」样式;place_name = 「自定义地点」,geoname_id 为空;与城市选择互斥(选自定义则清城市,反之亦然)
4. **删旧开关**:BirthFormView「手动输入经度」Toggle 与 `useManualLongitude`/`manualLongitude` 状态移除
5. 请求构造走同一新契约(longitude + timezone 显式)

## Acceptance criteria

- [ ] 三个入口的搜索 sheet 内都能进「自定义地点」
- [ ] 只填经度不选时区 → 校验拦截「请选择时区」;经度 200 → 拦截
- [ ] 填 117.3 + GMT+8 提交 → 请求 `longitude=117.3, timezone=Etc/GMT-8`(或所选区),排盘成功且真太阳时按 117.3° 计算
- [ ] 选「Asia/Shanghai」+ 1988-07-01 12:00 → 后端按夏令时 +09:00 解释(S02 用例在真实 UI 链路复验)
- [ ] Etc/GMT 组符号方向核对用例:选「GMT+8 固定偏移」发出的 tz 名解析回偏移恰为 +8(防 IANA 反符号坑)
- [ ] 自定义与城市选择互斥,来回切换状态干净
- [ ] `useManualLongitude` / `manualLongitude` 全仓 grep 零残留
- [ ] iOS 编译通过 + 新文案中英 xcstrings;视觉符合 `DESIGN.md`

## 红线与约束

- **客户端不做历法计算**:时区选择只传 IANA 名,**不在客户端算 offset**(展示样例文案除外,静态字符串)
- **错误显式传播**:校验失败内联报错;`Etc/GMT` 反符号坑靠单测钉死
- **不做**:经纬度双输入(纬度下游不用,不给用户添输入项;latitude 字段自定义地点时置空)
