## 背景

美区竞品 18 条差评（去重约 14 条），最伤的一类是「命盘不准」：出生时间被改、
「我是木牛不是水牛」、「没按农历新年算」、「AI 跟我争」。逐条对照本仓库代码后，
结论是：**我们的计算是对的，但展示层会让美国用户得出同样的结论**。

- 真太阳时：美国有夏令时、时区跨度大，夏天出生的人普遍被校正约 1 小时，不少人跨时辰
  （1990-07-15 10:00 实测：底特律 → 08:22，−98 分，跨时辰；埃尔帕索 → 08:48，跨时辰；
  洛杉矶 → 09:01）。用户会拿别家不做校正的 App 对照，时柱对不上 = 「你错了」。
- 年界：八字按立春换年，大多数生肖网站按农历新年换年。出生在两者之间的人生肖差一年
  （lunar_python 实测 1986-02-05：农历口径乙丑牛，立春口径丙寅虎）。
- 「木牛」= 年干五行 + 年支生肖（乙丑：乙木、丑牛），**不是纳音**（乙丑纳音是海中金）。
  西方用户会把「Year of the Ox」和「Day Master Water」拼成「水牛」。

## T1 · 后端：钟表时间对照柱 + 结构化夏令时标记（P0）

**问题**

- `backend/app/engine/bazi_engine.py:414-436` `_format_boundary_warning` 把真太阳时跨界与
  夏令时边角拼成**硬编码中文串**，iOS `ChartHeaderView.swift:46-52` 对所有语言原样展示
  （`⚠` + 朱红底）。英文用户看到的是一段中文红色警告。
- 现有 `boundary_crossed`（`core/true_solar_time.py:140-155`）判的是**日历日期**是否变化，
  不等于日柱是否变化：setSect(1) 下 23:00 换日，钟表 23:30 → 真太阳时 22:50 日期没变但
  日柱变了；钟表 00:20 → 前一天 23:40 日期变了但日柱没变。用它写「日柱按这一天排」会写错。
- 用户真正拿去比对的是「别家 App 不校正时给出的柱」，后端应直接给出这个对照。

**改法**

1. `backend/app/engine/bazi_engine.py`：在主排盘之后，**仅当 hour_known=true 且无柱歧义时**，
   用出生地钟面 naive 时间（不做真太阳时校正）再排一次四柱，同样强制 `setSect(1)`，只取
   四柱干支。抽成纯函数，例如 `_clock_time_pillars(birth_local_naive) -> dict[str, str]`。
2. `backend/app/models/bazi.py` `BaziCalculateResponse` 新增两个字段（Optional，老客户端无感）：
   ```python
   # 不做真太阳时校正、直接按钟表时间排的四柱干支（仅展示对照用，不参与
   # content_hash / 喜忌 / 任何判断）。时辰未知或柱歧义 → None
   clock_time_pillars: dict[str, str] | None = None   # {"year","month","day","hour"} → 干支
   # 夏令时边角结构化码，供客户端本地化；与 boundary_warning 中的中文描述一一对应
   dst_flags: list[str] = []   # 值域: "dst_ambiguous" / "dst_nonexistent" / "dst_transition"
   ```
3. `boundary_warning` 字符串**保留不动**（老客户端仍读它），只是新客户端不再渲染它。
4. 不改 `content_hash`、`calcRuleSnapshot`、`context_binding.py` 任何族的绑定字段。
   新字段不进任何 token。

**护栏**

- `cd backend && python -m pytest tests/test_bazi_calculate.py tests/test_true_solar_time.py tests/test_hour_unknown.py tests/test_context_binding.py`
- 新增用例：
  - 底特律 1990-07-15 10:00（`America/Detroit`, -83.05）→ `clock_time_pillars.hour` ≠ `pillars.hour.gan_zhi`
  - 上海 2000-01-15 10:00 → 四柱全相同
  - 钟表 23:30 → 真太阳时 23:00 前的案例 → `day` 不同（用现有经度把偏移推过 23:00 的城市造一个）
  - 时辰未知 → `clock_time_pillars is None`
  - 夏令时跳过小时案例 → `"dst_nonexistent" in dst_flags`
- 确定性：同输入两次调用结果相等（加一条断言）
