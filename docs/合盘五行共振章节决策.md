# 合盘「五行共振」章节改造设计决策

Generated on 2026-08-14（grill-me 会话锁定）
Status: ACCEPTED（待实施）

## 背景

现状合盘 AI 解读付费 4 章：爱情深度 / 合作事业 / 财运合拍 / 流年同步。

用户诉求起点：「如果是异性才有爱情章节（同性合盘去掉爱情章节）」。

Grill 过程中挖出更根本的动机：**合盘的产品定位不该窄化为「婚恋测算」，而该是「两人磁场是否合拍」**。爱情只是磁场契合的一个应用场景。同性/异性都该用同一套「能量互动」叙事，而不是同性简单删章。

辅因：
1. **术语错位**：LLM 展开「爱情深度」200-300 字时，大概率写出「夫妻/姻缘/婚配/配偶」等异性语境词，同性场景下不合适（现状客户端禁词清单只拦「必成/必分」类绝对结论，不拦关系预设词）
2. **理论限制**：八字传统合婚是阴阳配对（男命看财=妻、女命看官=夫），这套机制在同性合盘里无法套用，LLM 硬写只会糊弄

## Q1 产品定位升级（根因）

合盘 ≠ 婚恋测算。合盘 = **解读两人能量场如何互动**。

- 爱情/事业/财运是「磁场契合度」在 3 个应用场景的展开
- 流年是磁场契合的时间维度
- 异性/同性/友谊/合作，磁场互动机制（五行生克）完全相同，无需两套叙事

这个定位对异性用户也是升级而非降级：不局限于「是否结婚」，而是更接近命理本质。

## Q2 单轨不拆双轨（用户确认）

```
方案 B（选定）:
所有 _paid 4 章: 五行共振 + 合作事业 + 财运合拍 + 流年同步
```

否决的双轨方案（异性保留「爱情深度」+ 同性换「磁场合拍」）：
- App 内两套话语，认知割裂
- 2 套 prompt 模板管理成本
- 异性用户的「算姻缘」需求由 deep_analysis 单盘的「爱情」章节满足，合盘不需要重复这个角度

否决的隐式调整方案（章节名不动，prompt 内加条件分支）：
- LLM 可能不听话；章节名仍叫「爱情」但内容是别的，用户困惑

## Q3 章节名「五行共振」（用户确认）

用户偏好专业/命理机制向命名（否决了「磁场合拍」「能量互动」「亲密深度」）。

- 「五行共振」直接点出命理机制（五行生克互动），与「专业不忽悠」调性一致
- 与其他 3 章命名结构对齐（合作事业/财运合拍/流年同步 都是机制+维度式命名）
- 彻底与「爱情」「亲密」等关系类型词解耦，LLM 看到章节名不会往婚配方向写

## Q4 「五行共振」章节模板全文（实施直接抄）

替换 `COMPATIBILITY_PAID_TEMPLATE` 第一章「爱情深度」：

```
**第一章：五行共振**（200-300 字）
两人五行的生克共振：谁给谁补喜神、谁的旺相消耗对方、日主生克链路，
以及这些共振在两人互动中的体现。分 3-5 段，每段 2-3 短句。
每段聚焦一个具体共振点（滋养点 / 张力点 / 时间维度的稳定性）。
不预设关系类型（婚恋/友谊/合作），聚焦能量互动本身。
```

`COMPATIBILITY_TEMPLATE`（alias 6 章版）第三章同步替换（同样内容）。

设计考量：
- **机制打底**：谁补喜神/谁消耗/日主生克 —— 命理确定性内容（对齐红线「LLM 只润色不判断」，这些机制后端定性评估已给，LLM 展开）
- **落到互动体现**：纯机制会写成教科书，每段必须落到「在两人互动中体现为什么」，付费章节要让用户觉得「这 200 字跟我有关」
- **显式护栏**：最后一句「不预设关系类型（婚恋/友谊/合作），聚焦能量互动本身」—— 显式指令比章节名暗示更可靠
- 与免费第 2 章「互补与冲突总览」的区分：免费章是**广度**总览（互补给资源/冲突是雷区），付费「五行共振」是**深度**机制（生克链路+时间稳定性）

## Q5 护栏策略（用户确认：全局 + 局部混合）

### 全局护栏（加进 3 个合盘模板的「通用要求」）

```
- 叙事用「两人」而非「情侣/夫妻/朋友/合伙人」；不预设关系类型（婚恋/友谊/合作/亲情）
```

### 局部护栏（只给 2 个高风险章节）

| 章节 | 风险 | 局部护栏 |
|---|---|---|
| 基础相处模式（免费1） | 写「夜里对话」「周末共度」等同居/伴侣预设 | 聚焦互动节奏本身，不写同居/伴侣等具体生活场景预设 |
| 合作事业（付费2） | 写「夫妻共同产业」「合伙开公司」 | 聚焦公共目标层面的协作（涵盖夫妻共业/朋友共谋/合伙人共事），不写具体关系预设 |

中低风险章节（互补冲突/财运合拍/流年同步）靠全局护栏覆盖，不加局部（避免过度工程）。

## 风险

| 风险 | 缓解 |
|---|---|
| LLM 无视「不预设关系类型」护栏仍写关系词 | prompt 源头全局+局部双层护栏；上线后抽查解读文本，若漏网再扩客户端 ForbiddenWords |
| 「五行共振」太术语化，付费转化率下降 | 付费墙 title 直接用「五行共振·付费章节」点题；上线后看转化数据，若差可 A/B「磁场合拍」 |
| prompt_version +1 导致老用户已购解读缓存失效 | InterpretationCache 按 prompt_version 隔离，老缓存自然过期；entitlement 不受影响（按 compatibilityHash 绑定，非 prompt_version） |
| alias 模板（老客户端 6 章版）与新 iOS 4 章版不一致 | alias 模板第三章同步改名，保持品牌一致；alias 后续可删（老 build 淘汰后） |
