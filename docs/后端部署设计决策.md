## 0. 从代码推出的硬约束(不是选择,是事实)

## 1. 部署在哪 [待拍板]

### 推荐:**新加坡或东京**的一台 VPS

理由按权重:

1. **C6 排除大陆和香港**:服务器在大陆/香港直连 Anthropic/OpenAI 不通,只能全程走第三方中转——把模型可用性押在中转商上,且 `ai_provider/ai_model` 缓存身份(ADR-0009)会被中转商静默换模型污染。
2. **不用 ICP 备案**:大陆服务器 + 域名对外提供服务必须 ICP 备案(个人备案周期 2-4 周,且备案主体与"命理"内容有审核风险)。海外节点无此流程。
3. **两个市场都够近**:主受众是华人(简/繁)+ 英文。新加坡/东京到大陆 RTT 约 60-100ms、到台港 30-50ms、到美西 100-150ms。本应用单次请求耗时由 LLM 主导(10-90s),网络 RTT 可忽略。
4. **成本**:2 vCPU / 2-4 GB / 40 GB SSD 的机器 $10-25/月,v1 量级足够(排盘 CPU 很轻,重活都在 LLM 厂商那边)。

候选厂商(同等可用,选熟悉的即可):阿里云国际站新加坡、腾讯云国际新加坡、AWS Lightsail 东京/新加坡、Vultr / DigitalOcean 新加坡。
**大陆用户访问稳定性**:国际站新加坡(阿里/腾讯)对大陆线路通常优于欧美厂商;若后续大陆用户反馈慢,优先换线路而不是换架构。

### 不选的方案

| 方案 | 不选原因 |
|---|---|
| 大陆云(阿里云/腾讯云大陆区) | C6 + ICP 备案,见上 |
| 继续跑在 Mac + 内网穿透(frp / Cloudflare Tunnel) | 家宽断电断网 = 全站下线;付费用户买了解读打不开;Mac 睡眠/重启不可控 |
| Serverless(Cloud Run / Lambda / Vercel) | C1:SQLite + 本地图片需要持久盘;Lambda/Vercel 还有请求时长上限 < 生图 240s |
| Fly.io / Railway / Render 这类 PaaS + 持久卷 | 可行但无明显优势:卷只能挂一台机器,本质仍是单机;亚洲节点和大陆线路一般。若不想碰服务器运维,**这是第二选择** |
| K8s / 多机 | C1 + C4,v1 零收益 |

## 2. 部署形态

```
iPhone ──HTTPS──▶ api.<域名>  (DNS 直接解析,不过 CDN 代理,见 C3)
                     │
              ┌──────┴────────── VPS(新加坡/东京)─────────────┐
              │  Caddy :443  (自动签发/续期 Let's Encrypt)       │
              │     │ reverse_proxy,read timeout 360s           │
              │     ▼                                            │
              │  uvicorn app.main:app  容器内 8000 ×2 worker    │
              │     │                                            │
              │     ▼                                            │
              │  /srv/qicompass/data/  (qicompass.db + images/) │
              └──────────────────────────────────────────────────┘
                     │ 每日
                     ▼
               对象存储(异地备份)
```

### 2.1 进程托管 [待拍板:Docker 还是 systemd]

**推荐 Docker Compose(app + caddy 两个服务)**:
- 固定 Python 版本 + tzdata(C8)+ 依赖,Mac 上构建和服务器上运行同一镜像,避免"我 Mac 上能跑"。
- 回滚 = 切回上一个镜像 tag。

**备选 systemd + venv + Caddy**:少一层抽象,适合完全不想学 Docker;代价是服务器上 Python/依赖版本要手工管。

两者都是运维工具而非 Python 库依赖,但按 CLAUDE.md「不擅自加依赖」精神在此列出由用户确认。

### 2.2 入口:Caddy(推荐)vs Nginx

Caddy 一行配置自动 HTTPS + 续期;Nginx 需另配 certbot。无论哪个都必须:
- 读/写超时 ≥ 360s(C3,给 300s iOS 资源超时留余量)
- 请求体上限 1MB 足够(无上传)
- 透传 `X-Request-ID`(已有 middleware 会复用),加 `X-Forwarded-For`
- **uvicorn 端口不对公网暴露**:`run.sh` 现在硬编码 `--host 0.0.0.0`(Debug 真机连 Mac 用)。Docker Compose 形态下容器内绑 0.0.0.0 是正确的,但 compose 里**不 publish 8000 端口**(或只 publish 到 `127.0.0.1:8000`),只留 Caddy 对外 443;systemd 形态则把 host 改成 env 可配(生产 127.0.0.1)。**注意 `FORWARDED_ALLOW_IPS` 要与之一致**(见 §3)

### 2.3 worker 数、反代头与优雅停机

- `WEB_CONCURRENCY=2`(2 vCPU)。沿用 `run.sh` 结论。
- **✅ proxy-headers 已进 `run.sh`**(2026-10-08):`--proxy-headers --forwarded-allow-ips "$FORWARDED_ALLOW_IPS"`,信任地址经 env 配置(默认 `127.0.0.1`,适合反代与后端同机)。**Docker Compose(反代在另一容器)必须填 Docker 网段**(如 `172.18.0.0/16`)或反代容器 IP,否则 X-Forwarded-For 不被信任,全站匿名用户共享一份每日免费配额。CIDR 网段写法需 uvicorn ≥ 0.31(`requirements.txt` 已锁 `>=0.31,<0.53`;0.27~0.30 会**静默**按字面匹配、网段永不命中)。
- **待补 `--timeout-graceful-shutdown 200`**:发版重启时让进行中的 LLM 请求(≤150s)跑完,否则用户已扣次数的生成被砍断。Docker 对应 `stop_grace_period: 210s`。(LLM 监控的后台计数任务关停已有 lifespan join,`main.py` `wait_for_pending_records`,不受此项影响。)

## 3. 配置与密钥

生产 `.env` 放服务器 `/srv/qicompass/.env`,`chmod 600`,不进 git、不进镜像。与开发环境的差异:

| 变量 | 生产值 | 备注 |
|---|---|---|
| `JWT_SECRET_KEY` | `openssl rand -hex 32` 新生成 | **绝不能**沿用 `.env.example` 的 dev 值。**轮换影响(C9,2026-10-10 口径)**:登录 JWT 全部失效(用户重新登录)+ 所有已存命盘的 `context_token` 全部 403(iOS 端自动自愈,分模块:深度 403 摄入点就地静默重签、一次/盘/会话;每日清失效 token、下次进入重签;补存入参缺失的老盘与合盘提示重新排盘)——无孤儿化、付费权益不受影响(存服务端 DB),但会造成全用户一波重登录+重排盘,**上线前定好就别动** |
| `QICOMPASS_DB_PATH` | `/srv/qicompass/data/qicompass.db` | 挂载卷内 |
| `AI_PROVIDER` / `*_API_KEY` / `*_MODEL` | 生产 key(建议与开发 key 分开,便于按 key 看账单和吊销) | |
| `APP_STORE_*` 5 项 | 真值 | `.p8` 内容整段放 env;**production 缺配任一项会拒绝启动**(2026-10-07 收口,防"Mock 静默放行 = 免费兑换付费权益") |
| `APP_STORE_ENVIRONMENT` | `production` | 但见 §6 P0 |
| `FORWARDED_ALLOW_IPS` | 同机反代 `127.0.0.1`;Docker Compose 填网段如 `172.18.0.0/16` | **部署必须项**(2026-10-08):配错不报错,但匿名免费配额按反代 IP 计,全站共享一份。uvicorn ≥ 0.31 才认 CIDR |
| `QICOMPASS_FREE_DAILY_LIMIT` | 默认 `150`,可不配 | 免费 module 真烧 LLM 的服务端每日上限/IP+user(2026-10-08 拍板 150,CGNAT 共享出口不挤兑;缓存命中不计) |
| `QICOMPASS_PAID_DAILY_LIMIT` | 默认 `500`,可不配 | 付费生成独立分桶(2026-10-08/16 轮拍板:付费不豁免、独立桶、500 拦脚本滥用;缓存命中不计) |
| `QICOMPASS_REFUND_DAILY_LIMIT` | 默认 `5`,可不配 | 配额退款的每日次数封顶(2026-10-08:分类退+防"构造失败=免费烧 LLM") |
| `QICOMPASS_LLM_HEALTH_TOKEN` | **必配**,`openssl rand -hex 32` | `GET /api/health/llm` 的 Bearer。**不配 = 端点整体 404(fail-closed)**;该端点暴露 provider 原始错误片段(可能含中转地址),运维只读。token 须 ASCII、无首尾空白,违者启动 fail-fast |
| `QICOMPASS_LLM_ALERT_FAILURE_RATE` / `QICOMPASS_LLM_ALERT_MIN_CALLS` | 默认 `0.5` / `5`,可不配 | LLM 失败率告警阈值(2026-10-09):当前 UTC 小时桶内调用数 ≥ MIN_CALLS 且失败率 ≥ RATE 时打 `ERROR "ALERT llm_failure_rate"` 日志,恢复打 `ALERT_RESOLVED`(进程内 10min 节流,多 worker 独立)。**消费方式是看日志**(Docker json-file / `docker logs`),不外发 |
| `QICOMPASS_ALLOW_MOCK_APPLE` | **不配**(生产禁止) | 仅 dev 想走通 redeem 链路才设 `=1`;生产该值无意义(缺配直接拒启动) |
| `IMAGE_API_*` / `DAILY_IMAGE_LIMIT` | 真值 / 按预算 | |
| `GOOGLE_SIGN_IN_CLIENT_ID` | 真值(若开 Google 登录) | |
| `WEB_CONCURRENCY` | `2` | |

`JUDGE_*`(evalkit 裁判)生产不需要;evalkit 与其 8899 UI **不进生产镜像**(对齐评测机设计决策)。

## 4. 数据与备份

- **SQLite 保持不变**:v1 流量下单文件 WAL 完全够用,换 Postgres 是 v2 问题(触发条件:需要第二台应用服务器)。
- **备份**(每日 cron):
  1. `sqlite3 qicompass.db ".backup /tmp/qc-$(date +%F).db"` —— 必须用在线 `.backup`,**不能**直接 `cp`(WAL 模式下会拿到不一致快照)
  2. gzip 后上传对象存储(同厂商另一地域或 Cloudflare R2 / Backblaze B2),保留 30 天
  3. `data/images/` 可不备份(丢了按需重生成,仅成本)
- **恢复演练**:上线前至少做一次"新机器 + 最新备份 → 服务起来 → 付费记录还在"。没演练过的备份不算备份。
- 可选增强 [待拍板]:Litestream 持续复制 SQLite 到对象存储(RPO 秒级)。属新工具,v1 每日备份够用则不引入。

## 5. 发版流程(手工,对齐"本地优先 / 不接 GitHub Actions")

> `docker build` 步骤依赖 S2 的 Dockerfile/compose 落地(§7 S2 待补,当前
> 仓库尚无);S2 前的临时替代 = rsync 源码到服务器、在服务器上 build。

```
Mac:  pytest 全绿 → docker build -t qicompass-api:<git sha> → push 到镜像仓库
      (或 rsync 源码到服务器再 build,省一个镜像仓库)
VPS:  备份一次 db → 改 compose 里的 tag → docker compose up -d
      → curl https://api.<域名>/api/health 确认 provider/model
      → curl -H "Authorization: Bearer $QICOMPASS_LLM_HEALTH_TOKEN" \
            https://api.<域名>/api/health/llm  (确认监控端点活着)
回滚: 改回上一个 tag → up -d(schema 只 CREATE IF NOT EXISTS,向后兼容回滚安全)
```

发版会造成数秒不可用;v1 可接受(单机零停机需要双实例 + 共享 SQLite,不值得)。

**provider/model 切换**是部署事件(ADR-0010):改 `.env` 重启即可,客户端靠 `/api/health` 身份自动隔离缓存。

## 6. 上线前必须补的代码缺口

### P0:生产后端要能验沙盒交易(App Review 会用沙盒买)

C7:当前 `APP_STORE_ENVIRONMENT=production` 时,后端只用生产环境查 transaction。但:
- **App Review 审核员在生产构建里用沙盒账号购买**
- **TestFlight 的购买也全是沙盒**

→ 生产后端对这些交易 `getTransactionInfo` 返回 not found → redeem 失败 → 审核员买完看不到内容 → **被拒**(Guideline 2.1 常见拒因)。

Apple 官方建议:先查 production,返回"交易不存在"再查 sandbox。改法:`AppleServerAPIClient` 持两个 client/verifier,`verify_transaction` 生产优先、not-found 回落沙盒;webhook 同理按 JWS 里的 `environment` 选 verifier。entitlement 行建议记录 `environment` 列,方便对账时排除沙盒记录。
(注:这不违反 ADR-0010「无 fallback」——那条管 AI provider;这里是 Apple 官方规定的两环境协议。)

### P1

- **✅ LLM 成本护栏已落地**(2026-10-07/08,代码侧先行,不再是缺口):免费/付费/退款三档服务端每日上限(§3 表,缓存命中不计、付费独立分桶)+ context 长度上限(4096/chart 64KB/总量 128KB)+ context_token 绑定(买一次盘不能再给任意盘生成付费内容)+ 免费真烧 LLM 计数(登录按 user_id 匿名按 IP,IPv4 映射归并/CGNAT 分桶已处理)。**剩厂商侧兜底**:Anthropic/OpenAI 控制台设月度消费上限,上线时一并设好。
- **`run.sh` 生产化(部分落地)**:✅ proxy-headers/forwarded-allow-ips(§2.3);**待补** host 改 env 可配(systemd 形态需 127.0.0.1,Docker 形态靠不 publish 端口兜住)与 `--timeout-graceful-shutdown 200`(§2.3)。
- **iOS Release `BACKEND_BASE_URL`** 从占位换成真域名(`project.pbxproj` Release 段)。
- App Store Connect 填 Server Notifications V2 URL:`https://api.<域名>/api/webhooks/appstore`(生产 + 沙盒两个都填同一地址)。

### P2

- **✅ 内建 LLM 监控已落地**(2026-10-09/10):`MeteredAIClient` 按小时桶计数 + 失败率 `ALERT`/`ALERT_RESOLVED` 日志 + `GET /api/health/llm` 数据出口(Bearer 鉴权,§3)。**仍建议**外部可用性监控(UptimeRobot / Better Stack 免费档,每 5 分钟打 `/api/health`,挂了推手机)——内建监控只看 LLM 维度且依赖服务本身活着。
- 日志:Docker json-file 配 `max-size` 轮转,避免磁盘写满;`ALERT llm_failure_rate` 也在这些日志里,免费档监控方案若支持日志关键字告警可顺手接上。v1 不上集中日志。
- 服务器基础加固:只开 22/80/443,SSH 仅密钥登录,开自动安全更新。
- 可选 staging:TestFlight 与正式版共用同一生产后端(P0 修好后沙盒交易能正确处理);v1 **不建**独立 staging,真要试新版后端,在同机起第二个 compose 项目挂 `staging-api.<域名>` 即可。
