# S11 程序化二批:今日 / 60 日柱 / 日主×月令 / 配对

- **类型**: AFK(模板与数据)+ HITL(用户抽审)
- **Blocked by**: S07(首批定稿,确立语气基准);今日页依赖 S04 的日历导出
- **覆盖规格**: `design-ref/website/README.md` §3(二批行)、§4.3(日柱 / 配对 H2 骨架)
- **Parent**: `docs/官网实现-slices/README.md`

## What to build

| 页面 | 数量 | 数据来源 | 独有内容(防薄内容) |
|---|---|---|---|
| `/en/today` | 1(每日重建) | `export_site_calendar.py` | 今日年月日干支、农历、节气、当前与下一时辰表;链到今日日柱页 |
| `/en/day-pillar/{gan-zhi}` | 60 | 引擎导出 | 干支与纳音、自坐十神与长生、**未来 12 个同柱日期**、该日柱出生者的倾向描述 |
| `/en/day-master/{dm}/born-in-{branch}-month` | 120 | 引擎季节规则 | 得令与否、调候需求(后端规则给出)、与本月其他日主对比 |
| `/en/compatibility/{a}-and-{b}` | 55 | 十神关系 + 天干五合 / 相冲 | 双向十神关系、合冲、「只看日主的局限」+ App 合盘 CTA |
| `/en/five-elements/too-much-{el}` / `missing-{el}` | 10 | — | 五行过多 / 缺失的表现与常见调和思路(不写「化解 / 改运」) |

做法:
1. 数据导出脚本 `tools/export_site_programmatic.py` 调后端引擎生成 JSON(确定性,进 git)
2. 每类页面一个模板,事实字段来自 JSON;叙述段落 AI 起草后进 content collection,同样走 `check_site_content.py`
3. **用户抽审**:每类随机抽 10%(至少 3 页)给用户过目;通过后整类发布;不通过则改模板或规范后整类重抽
4. 发布节奏:按类分批,每天最多一类,并按规格 §5 规则从已有流量页加内链

## Acceptance criteria

- [ ] 60 日柱页的「未来同柱日期」与 `lunar_python`(setSect(1))一致(抽查 5 页)
- [ ] 配对页只有无序 55 页,反序 URL 301
- [ ] 每页至少 300 词独有正文(去掉模板公共文字后),`check_site_content.py` 增加此检查
- [ ] 用户抽审记录写进各页 `reviewedBy`(抽审页)与类级记录
- [ ] sitemap 分片自动纳入新类型
