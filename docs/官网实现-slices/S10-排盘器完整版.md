## What to build

1. **生辰帖**:日期 / 时间 / 不知时辰 / 城市自动补全 / 性别 / 规则说明。城市数据:从 `tools/build_city_db.py` 产出的城市库导出一份精简 JSON(人口 ≥ 15 万 + 全部首都,按需懒加载,首屏不加载),或调用后端城市搜索(若已有端点)—— 二选一并在报告里说明体积
2. **结果区**:按设计稿顺序渲染 `/api/public/chart` 的响应:元信息(真太阳时修正量)→ chips → 四柱表 → 五行条 → 旺衰与喜忌 → 大运横轴(当前步加朱点,「当前」按访客当前年份判断)→ 神煞 chips → 虚线锁框捌章 + App CTA
3. **渐进增强**:表单是原生 GET 到 `/en/bazi-calculator?d=…`;有 JS 时拦截提交、fetch 接口、原地渲染、`history.replaceState`;无 JS 时由 Cloudflare Pages Function 服务端调用接口渲染(若不想引入 Functions,则在无 JS 时显示「需要启用 JavaScript」的说明 —— 二选一,报告里写明)
4. **晕墨动效**:四柱按列延迟 0 / .3 / .6 / .9s 依次显现;reduced-motion 同时显示
5. **结果里的每个字 / 十神 / 神煞都是内链**,带释义卡
6. **从格**:旺衰显示「Special pattern」,喜忌显示「left open」;**时辰未知**:时柱虚线圆位 + 「Hour unknown」
7. **noindex**:带参数的 URL 输出 `noindex,follow`(S06 机制)
8. **日主查询**:`/en/day-master-calculator` 独立页 + 知识页右栏小工具,只填日期,调同一接口取日柱
9. **切换**:`features.calculator=on`;首页 hero 换回排盘表单;排盘器页 JSON-LD 加 `WebApplication` + `HowTo`
10. 错误态:接口 429 / 5xx / 网络失败 → 原地显示可重试的说明,**不显示假数据**

## Acceptance criteria

- [ ] 1992-04-18 09:30 北京 男:四柱与设计稿样例一致(壬申 甲辰 甲子 己巳,首步大运乙巳);起运年龄、旺衰、喜忌以接口为准(设计稿里是占位)
- [ ] 与 App 同一输入同盘(抽 5 组,对照 iOS 排盘结果截图)
- [ ] 浏览器 Network 面板:除 `/api/public/chart` 外没有任何历法相关计算或第三方请求
- [ ] 带参数 URL 有 `noindex`;sitemap 不含带参数 URL
- [ ] 接口失败时页面不崩、无假数据
- [ ] Lighthouse 移动端 Performance ≥ 90(含城市数据懒加载)
