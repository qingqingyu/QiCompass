# S05 一期排盘器页 + 转化组件 + 站务页

- **类型**: AFK,含 HITL 步骤(Buttondown 账号、隐私政策定稿)
- **Blocked by**: S03
- **覆盖规格**: `design-ref/website/README.md` §4.2(方法论 / FAQ 部分)、§7、§12(分期表)
- **视觉稿**: `docs/design-ref/website/calculator.html`(一期只做其中的头部、方法论、FAQ;生辰帖按注释换成锁框)
- **Parent**: `docs/官网实现-slices/README.md`

## What to build

1. **全局开关** `site/src/config.ts`:`features.calculator: 'off' | 'on'`、`cta.state: 'prelaunch' | 'live'`、`appStoreUrl`、`buttondownList`。所有 CTA 组件只读这里
2. **`NotifyOrAppStore` 组件**:`prelaunch` → Buttondown 嵌入表单(纯 HTML POST,带隐藏字段记录来源页);`live` → App Store 徽章(可选桌面端二维码)。同一组件,两态由配置切换
3. **`/en/bazi-calculator` 一期版**:H1 + 答案段(照设计稿)→ 生辰帖位置换成**虚线锁框**:「Opening soon」+ 一句说明 + 邮箱表单 → 方法论四格 → FAQ → JSON-LD(`WebApplication` 先不输出,一期只输出 `BreadcrumbList` + `FAQPage`,避免声明一个还不能用的应用)
4. **站务页**:`/en/app`(App 介绍 + 捌章清单 + CTA,复用首页 App 区)、`/en/about`(方法与出处,E-E-A-T:确定性引擎、真太阳时、23:00 换日、《三命通会》单一查表、内容生产流程「AI 起草 + 引擎核对 + 人工过目」)、`/en/privacy`(以 `tmp/app-store-launch/privacy-policy.md` 草稿为底,补 Buttondown 与 TelemetryDeck 两条,联系邮箱 `hello@knowfate.app`)
5. zh-hant 三页同步

## HITL 步骤(做到这里停下,列给用户)

- 用户注册 Buttondown 并提供 list 名(或你给出注册步骤,用户完成后填进 `config.ts`)
- 隐私政策定稿由用户过目确认后才能 `published`
- `tmp/` 是 gitignore 目录,若本机没有 `privacy-policy.md` 草稿,向用户索取,不要自己编写法律文本的实质条款

## Acceptance criteria

- [ ] 切换 `cta.state` 后重新构建,全站所有 CTA 位置同时切换,无遗漏(grep 构建产物验证)
- [ ] `features.calculator=off` 时全站没有指向排盘结果的表单提交
- [ ] 邮箱表单关 JS 可提交(原生 POST)
- [ ] 排盘器一期页视觉与设计稿头部 / 方法论 / FAQ 一致,锁框符合 DESIGN.md 虚线语义
- [ ] 隐私政策页包含 `hello@knowfate.app`,不出现任何私人邮箱
- [ ] `check_site_content.py` PASS
