# S02 内容模型 + 术语单一事实源 + 内容校验脚本

- **类型**: AFK
- **Blocked by**: S01
- **覆盖规格**: `design-ref/website/README.md` §3(URL)、§4.3(各类型 H2 骨架)、§5(内链规则)、§8(内容红线)
- **Parent**: `docs/官网实现-slices/README.md`

## What to build

1. **术语导出**:`tools/export_site_terms.py` 从 `backend/app/engine/term_translations.py` 读取天干、地支、五行、十神、纳音、十二长生、神煞的 zh / zh-hant / en 三语值,输出 `site/src/data/terms.json`(进 git,确定性排序)。脚本**直接 import 或静态解析**后端模块均可,但不复制词表
2. **扩展 `tools/check_term_sync.py`**:新增一组比对 —— `site/src/data/terms.json` 与 backend 表**键集合 + en 值 + zh-hant 值三相等**。站点任何地方出现的术语译名都必须来自这个 JSON
3. **Astro content collections**(`site/src/content/`),每种页面类型一个 collection,frontmatter schema(用 Astro 内置的 zod schema,不加依赖):
   - 公共字段:`title`(≤60 字符)、`description`(140–160 字符)、`slug`、`lang`、`inShort`(≤60 词)、`updated`、`published`、`faq: [{q, a}]`(2–4 条)、`reviewedBy`(人工过目记录:日期 + 审阅人,**为空则不允许发布**)
   - 类型字段:日主页 `stem`、`element`、`polarity`、`image`;十神页 `god`;神煞页 `star`、`lookupBasis`;指南 `readingMinutes`;生肖页 `animal`、`branch`、`element`、`friends`、`clash`(关系字段由构建期从后端 `branch_relations.py` 导出,不手填);生肖年份页 `year`、`yearPillar`、`startsAt`、`endsAt`(立春时刻,引擎导出)
   - 正文用纯 Markdown(不用 MDX);H2 用 `## {编号}|{标题}` 之类的约定或 frontmatter 的 `sections` 数组,由模板渲染大写数字编号 —— 选一种并写进 `site/CONTENT_GUIDE.md`
4. **术语自动内链**:写一个 remark 插件(放在仓库内,不发包),按 `terms.json` + 页面 URL 表,把正文里**每个术语的首次出现**包成 `<a class="term" data-zh data-title data-def href>`;已经手写成链接的跳过;本页自身不链
5. **内容校验脚本** `tools/check_site_content.py`(纯 stdlib + import 后端 `app.ai.forbidden_words`):
   - 每个内容文件过 `forbidden_words.scan()`,命中即 FAIL
   - 额外禁词(英文):`accurate`、`predict(ion)`、`guarantee`、`lucky charm`、`cure`、`remedy`、`change your fate`;禁止格局硬分类词(`… structure` 作为结论,如 "Direct Officer structure",以及中文「正官格 / 偏印格 / ……格」)
   - frontmatter 长度规则、`reviewedBy` 非空才可 `published: true`
   - 每页正文出站内链 ≥ 8 条,且全部指向存在的页面(死链 FAIL)
   - 退出码:0 PASS / 1 FAIL / 2 脚本错误
6. **`site/CONTENT_GUIDE.md`**:给写内容的人(或 AI)看的写作规范 —— 语气(专业不忽悠)、句式(倾向 / 传统上 / 命局呈现)、各类型 H2 骨架(抄规格 §4.3 表)、事实来源(只能来自后端引擎和《三命通会》查表)、禁止事项

## Acceptance criteria

- [ ] `python3 tools/export_site_terms.py` 幂等,产出与后端表一致
- [ ] `python3 tools/check_term_sync.py` PASS;故意改坏 `terms.json` 一个 en 值 → FAIL
- [ ] `python3 tools/check_site_content.py` 对一份放了禁词的测试内容 → FAIL 并指出文件和行;对合规内容 → PASS
- [ ] 一个缺 `reviewedBy` 却 `published: true` 的文件 → 构建失败(不是警告)
- [ ] remark 插件单测:同一术语只链首次;标题里不链;已有链接不重复包
- [ ] `CONTENT_GUIDE.md` 写完,S07 直接照它产内容

## 实现锚点

- `backend/app/engine/term_translations.py`:`HEAVENLY_STEMS_EN` / `EARTHLY_BRANCHES_EN` / `TEN_GODS_EN` / `NAYIN_EN` / `TWELVE_STAGES_EN` / `SHENSHA_EN` 及 zh-hant 表
- `backend/app/ai/forbidden_words.py`:`scan(text) -> list[str]`
- `tools/check_term_sync.py`:现有 ①–④ 组比对,新增一组(站点),保持同样的输出格式与退出码

## 红线与约束

- 术语:**zh-hant 以 iOS 人工校对稿为锚**(见 CLAUDE.md「三语模板/术语同步守护栏」),站点不得单侧改词
- 校验脚本不 import 第三方库;不接 GitHub Actions(本地优先),把「动了 site/src/content 必须跑 check_site_content.py PASS」写进 `site/CONTENT_GUIDE.md` 和 CLAUDE.md 的项目约束段
