# S07 首批内容 ~40 页

- **类型**: **HITL** —— 每一页都要用户本人过目后才能发布
- **Blocked by**: S02(内容规范与校验)、S03(模板)
- **覆盖规格**: `design-ref/website/README.md` §1、§3(首批)、§4.3(H2 骨架)、§8
- **Parent**: `docs/官网实现-slices/README.md`

## What to build

首批页面(en 先行,zh-hant 在 en 定稿后翻译,同样过目):

| 类型 | 数量 | 优先顺序 |
|---|---|---|
| 日主 | 10 | 甲 → 癸 |
| 十神 | 10 + 总览 1 | 先做搜索量最大的:Seven Killings、Eating God、Hurting Officer、Direct Officer、Indirect Resource |
| 五行 | 5 总览 + 总览 1 | 「too much / missing」放二批 |
| 神煞 | 6–8 + 总览 1 | Peach Blossom、Nobleman、Travelling Horse、Academic Star、Canopy Star、Goat Blade(用户可调整) |
| 指南 | 3–5 | How to read a BaZi chart、Unknown birth time、True Solar Time、Day Master strength、Chinese hours(时辰盘链接的落点) |

## 生产流程(每页)

1. **事实骨架**:从后端引擎 / 查表取事实(十神关系、季节旺衰、神煞查法),写进 frontmatter 和速查表 —— 不凭记忆写命理事实
2. **起草**:按 `site/CONTENT_GUIDE.md` 的该类型 H2 骨架起草正文;语气「专业不忽悠」
3. **自检**:`python3 tools/check_site_content.py` PASS(禁词 / 格局硬分类 / 长度 / 内链 ≥8 / 无死链)
4. **交给用户过目**:一次提交 3–5 页,附每页的 title、In short、目标关键词;**停下等用户反馈**
5. 用户通过 → 填 `reviewedBy`(日期 + 用户)→ `published: true`
6. 发布节奏:上线(S08)前可以攒;上线后**每天最多 1 篇**(规格 §8)

## Acceptance criteria

- [ ] 首批页面全部 `reviewedBy` 有记录
- [ ] `check_site_content.py` 全部 PASS
- [ ] 每页 In short 是独立可引用的定义句
- [ ] 每页至少 8 条正文内链,且日主页「与其他九日主」、季节表的链接在目标页未发布时按 S04 的规则显示为灰色
- [ ] 没有任何一页出现格局硬分类、预测性表述或真实名人命盘

## 红线

- 不写名人(真实人物)命盘
- 喜忌相关表述只能是「传统上 / 通常 / 倾向」+ 后端规则口径
- 不批量生成后一次性发布
