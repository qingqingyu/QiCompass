# S12 增长运营手册(runbook)

- **类型**: HITL(持续)
- **Blocked by**: S08(站点上线且 Search Console 有数据,通常上线 2–4 周后)
- **覆盖规格**: `design-ref/website/README.md` §1、§8
- **Parent**: `docs/官网实现-slices/README.md`

## What to build

写 `docs/官网增长运营手册.md`,把视频案例的「每天一篇 + 盯高曝光低点击」变成可以每周照做的步骤,并配一个辅助脚本:

1. **`tools/gsc_weekly.py`**:读取用户从 Search Console 导出的 CSV(**不接 API,不存凭据**),输出三张清单:
   - A 类:曝光 > 500、CTR < 1%、平均排名 8–30 的页面 → 改 title / description / In short
   - B 类:有曝光但站内没有对应页面的查询词 → 新页面候选(按曝光排序)
   - C 类:排名 1–7 但 CTR 低于同排名均值的页面 → 改 title 吸引力
2. **每周流程**(写进手册):周一导出 CSV → 跑脚本 → 选本周 5–7 个任务(每天 1 个)→ 每个任务走 S07 的生产流程(起草 → 校验 → 用户过目 → 发布)→ 发布当天从 3 个相关高流量页加内链 → 第 3–4 天回看
3. **记录**:`docs/官网增长日志.md` 每周一行(本周改了什么、上周改动的排名 / CTR 变化)
4. **转化回看**:TelemetryDeck 里按 CTA slot 看点击率,目标知识页 → 排盘器 ≥ 15%、排盘器 → App ≥ 10%;低于目标时调整 CTA 文案或位置(只改文案和位置,不加弹窗)

## Acceptance criteria

- [ ] 用一份示例 CSV 跑 `gsc_weekly.py`,三张清单输出正确
- [ ] 手册写清每一步谁做(AI / 用户)、产出放在哪
- [ ] 不接任何第三方 API、不保存任何账号凭据

## 红线

- 每天最多发布 1 篇;不做批量灌内容
- 改 title 只为更准确地描述页面,不写标题党、不写预测性承诺
