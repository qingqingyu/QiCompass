今日问事 · 多会话

聊天页左上三叠横墨 → 左滑会话抽屉 → 每次对话一条
浏览器里可以真点:
① 点左上角三道杠 → 抽屉从左滑出(压暗后面);
② 「今天」区点任一条切换会话(当前条带墨青灯点);
③ 点「往日」任一条 → 只读态(输入栏换成提示条 + 新开一问);
④ 「＋ 新开一问」→ 全新开场白 + 候选问题;
快捷参数:?drawer=1 直接开抽屉。

你的指令怎么落

  1. 三道杠:沿用「深度」tab 的三叠横墨线描(中画略重),不引入系统 hamburger 图形——品牌语言不打折。
  2. 左滑抽屉:宽 78%,纸面浮层 + 右缘 hairline;标题「问事录」与「命书」同族的书卷命名。
  3. 每次对话一条:标题 = 首问截断(确定性,不烧 LLM);副行预览末轮;当前条 = 墨青灯点 + 淡墨底(与窄条灯点同语言)。

生命周期(我的推断,可否决)

  1. 今日线可聊 / 往日线只读 / 不跨天续聊:盘面每日换,旧线里的回答踩的是旧盘;续聊会出现「昨天的盘说X、今天的盘说Y」的语义打架,且后端作答端点把上下文钉死在「今天的盘」,续聊要大动(prompt 版本/缓存键/计费口径全部重拍)。往日价值在回看,不在续问。
  2. 若你要的是「往日也能接着聊」:说一声,那是另一套代价,我会重新出方案。

交互口径

  1. 窄条点开 = 最近一条会话(今日页入口不变,不开列表);没有会话则新开。
  2. 每条线独立上下文:各自 ≤20 轮(服务端契约本来如此),互不挤占。
  3. 跨午夜还在聊天页:当前线自动转只读 + 提示「已换日」,续问 = 新开一问(新线踩新盘)。
  4. 计费照旧按问题计,不按线计;次数尽卡片态在每条线内独立出现。

落地时的数据活(iOS 侧)

  1. SwiftData 新实体 AskConversation:归属 (contentHash, dateKey) 双键 + 标题 + 消息子实体;顺手修掉「杀 App 丢会话」(现单会话只活在内存里,这是既有缺陷)。
  2. 换盘:抽屉只显当前盘的会话(现行为:对话随旧盘走,不迁移)。
  3. 后端零改动:作答端点无会话概念(每次带 history 重答),多会话纯客户端组织。
  4. 切片建议:S1 SwiftData 模型+现有单会话迁移 → S2 顶栏钮+抽屉 UI → S3 切换/新开/只读态/跨午夜 → S4 真机走查。
