# 0004 — 喜忌 = 后端确定性规则引擎(扶抑 + 调候),LLM 只润色

Status: accepted (2026-07-09)

命局喜用五行 + 忌五行由后端规则引擎给出,不交给 LLM 判断。主规则 = 扶抑法(身强用克泄耗,身弱用生扶);修正规则 = 调候法(生在极寒/极热月时叠加调候用神,优先级高于扶抑)。结果存进 `ChartSnapshot.payload`,LLM prompt 里以结构化字段传入,LLM 严禁修改。

**Why**: 同一个命盘今天喜火明天喜水,用户立刻不信你。每日运势作为高频回访入口,喜忌必须 100% 确定性 + 可缓存 + 可复现。LLM 即使能力再强也不能保证同输入同输出,且会把流派分歧带进产品。

**Surprising without context**: 项目把"判断命理"放在最确定的层(规则引擎 if-else),把"说人话"放在最不确定的层(LLM)。这跟"AI 八字 App"的直觉相反 — 一般人会以为 AI 负责判断。

**Real trade-off**:
- ✅ 规则引擎 — 确定性 + 可缓存 + 跨用户共享,覆盖 ~90% 普通旺衰盘
- ❌ LLM 判断 — 灵活但不确定,无法缓存,流派分歧大
- ❌ 不给喜忌 — UX 残缺,用户期待看到

**Consequences**: 10% 从格/专旺边界盘不能硬塞扶抑(会得反结果),需独立处理 — 见 ADR 0007。规则引擎的权重(得令/得地/得势)需用 50 个真实命盘 spike 标定。
