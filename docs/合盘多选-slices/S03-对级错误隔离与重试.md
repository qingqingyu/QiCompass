# S03 对级错误隔离 + 单对重试

- **类型**: AFK
- **Blocked by**: S01（与 S02 可并行，合入时注意 S02 detail 态对失败卡片的处理约定）
- **覆盖决策**: D10（对级错误隔离：单对失败不拖垮列表）
- **Parent**: `docs/合盘多选设计决策.md`

## What to build

批量计算从「单对失败 → 整体 failed」升级为「单对失败 → 该卡片失败态 + 单对重试」：

1. **PairSummary 加状态**：`status: .computed / .failed(UserFacingError)`。S01 的 PairSummary 结构扩此字段
2. **批量 continue-on-error**：串行循环中某对 `runDeterministic` 抛错 → 该对 PairSummary 置 `.failed`，**循环继续**跑剩余对；整体列表仍正常呈现（全部成功 + 部分失败混合）
3. **失败卡片**：
   - 视觉：失败态卡片（错误摘要文案，DESIGN.md 语言，朱砂/destructive 点缀），不显示两句话（无数据）
   - 「重试」按钮：**单对重调** `runDeterministic`（复用该对请求构造）→ 成功后转 `.computed` 并刷新卡片
   - 失败卡片不可进详情（点击提示「重试成功后可查看」或禁用点击）
4. **整体 failed 保留范围**：仅系统级错误（名单加载失败、快照持久化层错误等与单对无关的错误）走整体 `failed`；单对 API 失败一律隔离
5. **对齐现有哲学**：与「AI 失败隔离」（阶段 2 失败不影响 ready）一致——确定性阶段同样隔离，不再整体 failed

## Acceptance criteria

- [ ] 断网/后端故障下批量计算：失败对卡片显示失败态 + 错误摘要，其余对正常显示两句话与标记
- [ ] 恢复网络 → 点失败卡片「重试」→ 该对单发一次 API → 成功转正常卡片；重试期间其他对无请求
- [ ] 失败卡片点击不进入详情（禁用或提示先重试）
- [ ] 全部对失败时列表仍呈现（N 张失败卡片），不崩不整体 failed（系统级错误除外）
- [ ] 单对重试再次失败 → 卡片保持失败态，可继续重试（不吞错，错误显式展示）
- [ ] 测试：注入单对失败的 mock orchestrator → 断言其余对正常、失败对 status 正确、重试只调单对 API

## 红线与约束

- **D4/D12 红线**：重试不触碰付费/次数/后端；确定性阶段失败无付费概念
- **错误显式传播**：失败卡片展示真实错误摘要（`UserFacingError` 现有转换链），不用笼统「出错了」掩盖
- **i18n**：文案跟随现状中文硬编码
- **并发**：重试与批量循环互斥（重试期间该对不在批量循环中；批量进行中不显示重试），避免同对并发双请求

## 测试

- VM 层：mock orchestrator 单对抛错 → 批量 continue-on-error、PairSummary 状态正确、重试仅单对 API 调用
- 边界：首对失败 / 末对失败 / 连续多对失败 / 全部失败
