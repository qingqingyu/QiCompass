# S05 增量预查（canonicalKey 命中跳过 API）

- **类型**: AFK
- **Blocked by**: S01
- **覆盖决策**: D7（点「开始合盘」先本地预查 canonicalKey，命中跳过 API）
- **Parent**: `docs/合盘多选设计决策.md`

## What to build

批量计算循环加本地预查层，内容寻址的自然收益——重算已算过的对不耗 API：

1. **逐对预查**：批量循环每对调 API 前先本地查：
   - 存档对方：A hash 与 B hash 已知 → `canonicalKey(aHash, bHash, context)` → `CompatibilitySnapshotStore.get(compatibilityHash:)` 命中 → 跳过 API
   - 临时对方：resolvedHash 已知（曾算过，S04 已回填）→ 同样预查；首次计算无 resolvedHash → 直接调 API
2. **命中路径**：用本地 `CompatibilitySnapshot` 重建该对 PairSummary（`decodeQualitative` 出两句话；`interpretation != nil` 出「已解读」标记），不调 API、不产生新快照
3. **未命中路径**：走 S01 现状（调 `runDeterministic` → upsert）
4. **换 context 语义**（D8 配套）：hash 含 context → 换 context 全部未命中 → 全调 API（确定性便宜，可接受）
5. **新增查询**：`CompatibilitySnapshotStore.list(personAHash:context:)`（按 A + context 查全部对，createdAt DESC）——本 slice 落地此查询，S06 恢复列表直接使用

## Acceptance criteria

- [ ] 同名单同 context 二次点「开始合盘」→ 全部对秒出（日志验证零 API 调用）
- [ ] 名单新增一对重算 → 仅该对调 API，其余对本地命中
- [ ] 换 context 重算 → 全部未命中 → 全调 API
- [ ] 命中路径卡片内容与 API 路径一致（两句话 / 已解读标记无差异）
- [ ] `list(personAHash:context:)` 返回该 (A, context) 全部快照按 createdAt DESC（供 S06）
- [ ] 测试：预查命中/未命中分支、canonicalKey 对 resolvedHash 适用性、list 查询排序与过滤

## 红线与约束

- **D4/D12 红线**：预查纯本地读，不触碰付费/次数/后端
- **错误显式传播**：本地快照 decode 失败（脏数据）显式 throw 走该对失败路径（S03 隔离），不静默跳过
- **i18n**：无新文案（本 slice 纯逻辑）
- **注意**：canonicalKey 长度必须按 UTF-8 字节数（`.utf8.count`），与后端对齐——现状实现已正确，勿改用 `.count`
