# S06 跨启动恢复 + 名单持久化 + 边界清理

- **类型**: AFK
- **Blocked by**: S01、S05
- **覆盖决策**: D5（跨启动恢复）/ D8（context 作用域：恢复按 (A, context)）/ D11（配置页预填持久化值）/ D13（失效 A hash fallback、无效名单 hash 清理、首次使用落现状流程）
- **Parent**: `docs/合盘多选设计决策.md`

## What to build

收口 slice：把名单/配置持久化，进 tab 默认恢复上次结果列表（纯本地，零 API）：

1. **UserDefaults 持久化**（VM 内小工具，读写 JSON）：
   - `compat.lastPersonAHash`：上次 A 盘 contentHash
   - `compat.lastContext`：上次 context（默认 "general"）
   - `compat.roster`：名单 = JSON `[personBHash]`（临时人用 resolved contentHash，S04 已回填）
   - 每次成功计算后写入；配置页改动时同步写
2. **恢复列表 = 已算对 ∩ 名单**（D5 核心）：
   - 进合盘 tab（0 快照之外）默认显示上次列表：`store.list(personAHash == A, context == C)`（S05 已落地）→ 按名单过滤 → createdAt DESC
   - **名单过滤的意义**：配置页删掉的对方，重启后不从快照库「复活」；快照本身保留（内容寻址可回溯，重新勾选秒回——S05 预查）
3. **恢复时清理无效名单项**：link 被删 / ChartSnapshot 不存在的 hash → 静默剔除 + 写回清理后的名单（防脏数据，不报错）
4. **A hash 失效 fallback**：持久化 A hash 查不到 link → fallback 最新 link
5. **配置页预填**：A 盘 = 持久化 A、勾选态 = 当前名单、context = 持久化 context（D11 配置页单一入口的收尾）
6. **首次使用**：0 已算对 → 自然落到现有 `.empty` / 配置页流程（S01 已有，本 slice 保证恢复路径不破坏）
7. **换 context 语义**（D8）：恢复按 (A, context) 查——hash 含 context；换 context 重算后恢复新 context 列表（per-pair context 不做，v2）

## Acceptance criteria

- [ ] 计算 3 对 → 杀 app 重启 → 进合盘 tab 直接显示 3 卡列表，全程零 API 调用（日志验证）
- [ ] 配置页删除 1 人 → 重算 → 重启 → 列表 2 卡（删除者不复活）；重新勾选该人 → 秒出（快照保留 + S05 预查命中）
- [ ] 删除 A 盘 link → 重启 → fallback 最新 link，不崩
- [ ] 名单含无效 hash（link 被删的对方）→ 恢复时静默剔除并清理持久化名单
- [ ] 换 context 重算 → 重启恢复的是新 context 的列表
- [ ] 配置页预填：A / 勾选态 / context 与上次一致
- [ ] 首次使用（0 已算对）→ 仍走 `.empty` / 配置页现状流程
- [ ] 测试：持久化 round-trip（三个 key 写入/读出）、名单过滤（已算对 ∩ 名单）、无效 hash 清理、A fallback

## 实现锚点（现状快照 2026-08-13，实施以代码为准）

- `Features/Compatibility/CompatibilityViewModel.swift` — 新增持久化小工具（UserDefaults 读写，可放 VM 内或独立文件）+ `loadArchivedCharts()` 后接恢复逻辑
- `Features/Compatibility/CompatibilityView.swift:52` — `.task` 入口接恢复分支
- `Services/CompatibilitySnapshotStore.swift` — 用 S05 的 `list(personAHash:context:)`
- `Services/UserSnapshotLinkStore.swift` — 校验 A hash / roster hash 是否仍有效（link 存在性）

## 红线与约束

- **D4/D12 红线**：恢复纯本地，零 API、零付费、零后端改动
- **D6 红线**：名单持久化只存 hash，不把临时人转 link
- **错误显式传播**：持久化 JSON 损坏 → 显式清空名单落配置页（日志记录），不静默吞；恢复快照 decode 失败走 S03 对级失败路径
- **i18n**：无新文案（清理静默、无用户可见提示）

## 测试

- 持久化 round-trip：写 → 杀 → 读三 key 一致（内存 UserDefaults 模拟重启）
- 恢复过滤：构造 3 快照（2 在名单 1 不在）→ 恢复出 2 张卡片
- 无效 hash 清理：名单含不存在 link 的 hash → 剔除 + 持久化名单更新
- A fallback：持久化 A 失效 → 选最新 link
