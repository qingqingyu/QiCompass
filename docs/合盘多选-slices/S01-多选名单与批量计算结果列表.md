# S01 多选名单 + 串行批量计算 → 结果列表（golden path）

- **类型**: AFK
- **Blocked by**: None — 可立即开始
- **覆盖决策**: D1（交互形态）/ D2（存档勾选 + 上限 8）/ D3（批量确定性计算）/ D9（列表卡片内容）/ D10（状态机 list 态）/ D11（列表纯展示）/ D13（名单空拦截、对方池空引导、切 tab 取消）
- **Parent**: `docs/合盘多选设计决策.md`

## What to build

合盘主流程从「1 对 1」改造为「多选名单 → 串行批量计算 → 结果列表」的 golden path：

1. **名单模型（VM 内）**：引入 `[RosterEntry]`，两种成员类型
   - `.archived(hash)`：从 UserSnapshotLink 池勾选（**A 盘自己从候选池中排除**）
   - `.temp(PersonBInput)`：保留现有单临时人模式（B 模式 B 表单），本 slice 暂限 1 条——S4 才扩为多个。**不回归现有临时输入功能**
   - 名单上限 8 人（UI 阻止添加第 9 个，存档勾选与临时人合计计数）
2. **配置页 B 区改造**：存档区由单选改为**多选勾选列表**（复用 ChartArchivePickerView 的视觉语言，新做多选变体）；保留现有「临时输入」单表单作为名单的一类来源
3. **批量计算**：点「开始合盘」→
   - 名单空校验拦截：「请至少选择一位对方」
   - `state = .computing(completed: 0, total: N)`，**串行**循环逐对调现有 `orchestrator.runDeterministic`（不做并发），每完成一对 `completed += 1`
   - 每对成功即 upsert CompatibilitySnapshot（orchestrator 现有行为）
   - 本 slice 单对失败 → 整体 `failed`（现状语义），S3 再引入对级隔离
4. **结果列表**：新增 `CompatibilityPairListView`，每对方一张卡片（D9）：
   - 名字（alias / 临时兜底名）+ 出生日期 + 日主
   - 两句话：`qualitativeAssessment.fiveElements`（五行互补）+ `dayMasterRelation`（日主关系）
   - 「已解读」标记：该对 `CompatibilitySnapshot.interpretation != nil` 时显示
5. **状态机**（`CompatibilityViewState`）：`configuring` 与 `ready` 之间插入 `computing(completed: Int, total: Int)` 与 `list([PairSummary])`；`detail` 态留给 S2
6. **列表纯展示**（D11）：toolbar「编辑名单」→ 回配置页并预填当前名单勾选态；列表无滑动删除
7. **边界态**（D13 本 slice 部分）：
   - 0 存档 → 现有 `.empty` 不变
   - ≥1 存档但对方池空（只有自己）→ 配置页显示「暂无对方命盘」+ 引导临时输入 or 去「我的」新建
   - 批量计算中切 tab → cancel computeTask（现状语义保持）

## Acceptance criteria

- [ ] 配置页 B 区可勾选多个存档对方；A 盘自己不出现在候选池
- [ ] 名单空（0 勾选且无临时人）点「开始合盘」→ 显示「请至少选择一位对方」，不发请求
- [ ] 勾选 N 人（含 1 存档 + 1 临时混合）→ `computing(i, N)` 进度 → 列表恰好 N 张卡片
- [ ] 卡片内容齐全：名 / 出生日期 / 日主 / 五行互补 + 日主关系两句话；已生成过 AI 的对显示「已解读」标记
- [ ] 添加第 9 个成员被 UI 阻止（上限 8）
- [ ] 列表 toolbar「编辑名单」→ 配置页，勾选态与名单内容保留
- [ ] 现有单临时人流程不回归（1 存档 + 1 临时 → 2 张卡片，临时人隐式落地行为不变）
- [ ] 对方池空引导文案可见（临时输入入口 + 去「我的」引导）
- [ ] 批量计算中切 tab → 任务取消，无残留请求
- [ ] 卡片视觉符合 `DESIGN.md`（纸白卡片 + hairline 分隔 + 4pt 圆角 + 朱砂点缀，无阴影/无渐变）
- [ ] VM 单元测试：名单空拦截、上限 8、串行批量顺序（i/N 递增）、混合名单请求构造正确
