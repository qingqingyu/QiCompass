# S02 点卡片进详情（NavigationStack push + 复用 CompatibilityMainView）

- **类型**: AFK
- **Blocked by**: S01
- **覆盖决策**: D1（结果列表 → 点卡片进详情）/ D3（AI 逐对按需，详情页内触发）
- **Parent**: `docs/合盘多选设计决策.md`

## What to build

结果列表 → 单对详情页的完整通路，最大化复用现有 1 对 1 详情实现：

1. **状态机加 `detail` 态**：`detail(PairSummary, CompatibilityResponse, InterpretState)`。点列表卡片 → 进入该对详情（NavigationStack push 或状态切换渲染，二选一实现，视觉与导航语义等价）
2. **详情页复用**：`CompatibilityMainView`（双盘对比 + 4 评估卡 + 流年同步 + AI 解读段）**零改动**复用，入参从当前对的快照/response 构造
3. **AI 解读逐对按需**（D3）：
   - `generateInterpretation()` 重构为按对触发：从 detail 态持有的 PairSummary 取 compatibilityHash
   - 现有全流程复用零改动：本地 24h 缓存查询 → entitlement 查 module（`compatibility_paid`/`compatibility_free`）→ 全局池次数 → API → 禁词扫描 → 缓存写入 → 长期快照同步
   - 每对独立 `InterpretState`（一对 fetching 不影响其他对）
4. **付费墙按对绑定**：`lastCompatibilityHashForPaywall` 语义按对化——detail 态的该对 hash，购买成功 → dismiss + 重新调该对的 generateInterpretation
5. **返回与标记刷新**：从详情返回列表 → 该对卡片「已解读」标记随 interpret 完成刷新（解读完成时列表态同步更新）

## Acceptance criteria

- [ ] 列表点任意卡片 → 该对详情完整呈现（双盘对比 / 4 评估卡 / 流年同步表 / AI 解读段）
- [ ] 详情内「生成合盘解读」只对该对触发；解读成功后返回列表，该对卡片显示「已解读」，其他对不受影响
- [ ] 详情内付费墙按该对 compatibilityHash 绑定；购买成功自动触发该对解读
- [ ] 已达每日上限时该对显示上限态（禁用 + 下次重置时间），其余对不受影响
- [ ] 返回导航语义正确：详情 → 列表 → 「编辑名单」→ 配置页
- [ ] 解读失败（禁词/网络）→ 该对 InterpretState 错误态，列表与整体状态不受影响
- [ ] 测试：detail 态进入/退出、按对 interpretState 隔离、返回后「已解读」标记刷新
