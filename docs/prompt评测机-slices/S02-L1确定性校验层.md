# S02 L1 确定性校验层

- **类型**: AFK
- **Blocked by**: S01
- **覆盖决策**: Q3(判据分层 — L1)
- **Parent**: `docs/prompt评测机设计决策.md`

## What to build

把 spike 里已验证的 schema 校验包装成 evalkit 的 L1 层。**这一层的工作量主要是搬运和加测试,不是新写判据**。

1. **`backend/evalkit/checks/deterministic.py`** — 迁入并包装:
   - `_MODULE_REQUIRED_FIELDS` — M0-M7 各自的必填顶层字段表
   - `_ARRAY_CONSTRAINTS` — 数组长度精确约束(`m2_high_low`: `early_warnings`=3 / `switch_actions`=3;`m3_system`: `environment_checklist`=5;`m4_health`: `imbalance_risks`=3 / `recovery_levers`=3 / `reset_7day`=7;`m5_wealth`: `income_forms`=6 / `asset_ideas`=3;`m7_manual`: `use_cases`=3 / `falsification_signals`=2)
   - `_V1_EXTENDED_FORBIDDEN_WORDS` — v1 §4 扩展禁词(注定 / 必然 / 命中该 / 逃不掉 / 破财 / 血光 / 克夫 / 大凶 / 劫难 / 寿元 / 绝症 / 必赚 / 稳赚 / 包治)
   - `m0_structure` 的 `structure_fingerprint` 非空 + ≤40 字

2. **对外签名(module-agnostic,Q1 要求)**:
   ```python
   def check_deterministic(
       module: str,
       parsed_output: dict[str, Any],
       engine_result: dict[str, Any],
   ) -> list[str]:
       """返回 failures 列表,空 = 全过。engine_result 本层不用,签名对齐 L2 便于统一编排。"""
   ```
   内部委托给既有 `validate_v1_module_output(module, parsed)`,**不重写判据逻辑**。

3. **禁词双层保持不变**:
   - 生产层走 `app.ai.forbidden_words.scan()`(`ABSOLUTE_CONCLUSIONS`)
   - 扩展层走 `_V1_EXTENDED_FORBIDDEN_WORDS`(**留在评测侧,不动生产词表**)
   - 两层命中分别成条 failure,便于 UI 区分"违反生产红线"与"违反 v1 §4 但生产未禁"

4. **未知 module 的处理**:`_MODULE_REQUIRED_FIELDS` 查不到的 module **显式报错**,不静默返回空 failures——静默通过会让新加模块悄悄失去 L1 保护。

5. **`runner.py` 接线**:每个模块生成后立即跑 L1,结果写进 `results.jsonl` 的 `l1` 字段:
   ```jsonc
   "l1": {"passed": false, "failures": ["缺字段:['core_loop']", "reset_7day 长度 5 != 期望 7"]}
   ```

## 红线与约束

- **单一事实源**:L1 判据只有一份实现。包装层可以加签名适配和错误信息格式化,**不得复制判据逻辑**
- **不扩生产禁词表**:`ABSOLUTE_CONCLUSIONS` 只读。扩展词表留在评测侧(决策文档「不做」节已列明理由)
- **错误显式传播**:未知 module raise;JSON 已在 S01 的 `parse_llm_json` 解析,本层拿到的是 dict,解析失败不该走到这里
- **module-agnostic**:签名带 `engine_result` 参数(本层不用)是为了与 L2 统一编排,二期接老 3 模块时 `runner` 不用改分支
- **不擅自加依赖**:纯标准库 + 既有模块

## 测试

新增 `backend/tests/test_evalkit_deterministic.py`,**全部用手写字典,零 API 调用**:

- 每个模块各一组正例(完整合法输出)→ `failures == []`
- 缺字段反例 → failure 文本含缺失字段名
- 数组长度错例(如 `reset_7day` 给 5 条)→ 命中长度 failure
- `structure_fingerprint` 超 40 字 / 为空 → 各自命中
- 生产禁词命中(如"注定分手")→ failure 标明是生产层
- 仅扩展禁词命中(如"稳赚")→ failure 标明是 v1 §4 扩展层
- 未知 module(如 `"m9_nonexistent"`)→ `pytest.raises`
