# S03 L2 接地校验层

- **类型**: AFK
- **Blocked by**: S01(**可与 S02 并行**)
- **覆盖决策**: Q3(判据分层 — L2)
- **Parent**: `docs/prompt评测机设计决策.md`

> **本系列价值核心**。L2 把"LLM 编造了后端没给的东西"从"要靠裁判读出来"变成"机器直接判死"。每多一条 L2,评测就便宜一分、稳一分。

## What to build

`backend/evalkit/checks/grounding.py`,五个**纯函数**,统一签名:

```python
def check_<name>(
    module: str,
    parsed_output: dict[str, Any],
    engine_result: dict[str, Any],
) -> list[str]:
    """返回 failures 列表,空 = 全过。纯函数:只读入参,不做 IO。"""
```

外加聚合入口 `check_grounding(module, parsed_output, engine_result) -> list[str]`,顺序跑五项并合并 failures。

**取文本的统一方式**:v1 输出是 JSON,把 `parsed_output` 里所有字符串叶子节点(含嵌套 list/dict)递归收集成 `list[str]`,再逐条扫。写成共享 helper `_iter_text_leaves(obj)`,五个校验共用,**不各写一份遍历**。

### 1. 喜忌一致性 `check_xiji_consistency`

对齐 ADR-0004 与 CLAUDE.md「喜忌走后端确定性规则引擎,LLM 只润色话术,**禁止**自行推断喜忌」。

- 事实源:`engine_result["favorable_elements"]` / `["unfavorable_elements"]`(英文 element 名 `wood/fire/earth/metal/water`,需经五行中英映射)
- 判据:文本中被明确**推荐**的五行不得出现在 `unfavorable` 里;被明确**规避**的五行不得出现在 `favorable` 里
- 实现:保守的模式匹配。推荐信号词(宜 / 喜 / 用神 / 有利 / 补 / 增强)+ 规避信号词(忌 / 避 / 不宜 / 克制 / 泄)在同句内与五行字共现时才判定;**跨句不判**
- `favorable_elements` 为空(special_pattern 盘)时本项跳过,交给第 4 项

### 2. 神煞不超界 `check_shensha_bounded`

对齐 ADR-0005(20 个固定清单,《三命通会》单一来源)。

- 事实源:`app/engine/shensha.py:240 SHENSHA_NAMES`(20 名)+ 本盘 `engine_result["shensha"]`(list of `{name, position, source}`)
- 判据两条,分别成 failure:
  - **越界**:文本出现的神煞名不在 `SHENSHA_NAMES` 里 → 编造了清单外神煞(如"天医""国印")
  - **未命中**:名字在清单内,但不在本盘 `engine_result["shensha"]` 的 `name` 集合里 → 把别的盘的神煞安到这盘上
- **清单从 `SHENSHA_NAMES` import,禁止复制第二份**(单一事实源红线)

### 3. 格局红线 `check_no_hard_geju`

对齐 ADR-0006 与 CLAUDE.md「MLLM 用『命局呈现××倾向』模糊叙事,**禁止**给出『正官格 / 偏印格』等硬分类结论」。

- 判据:扫十神 + "格"字的硬分类,词表明写在模块内:
  `正官格 / 七杀格 / 偏官格 / 正财格 / 偏财格 / 正印格 / 偏印格 / 食神格 / 伤官格 / 比肩格 / 劫财格 / 建禄格 / 羊刃格`
- 命中即 failure(这是红线,不打分)
- **只扫"××格"整词**,不扫单独的"格局"二字——后者是允许的中性表述

### 4. special_pattern 诚实 `check_special_pattern_honesty`

对齐 ADR-0007(从格阈值 + 诚实降级)。

- 触发条件:`engine_result["day_master_strength"] == "special_pattern"`(20 盘中的 5 盘),其余盘本项返回空
- 判据两条:
  - **不得编造喜忌**:此时 `favorable_elements` / `unfavorable_elements` 按设计为空,文本中不得出现明确的喜用五行推荐
  - **须诚实告知**:须出现"不入常格 / 不适用扶抑 / 特殊格局 / 从格"一类表述(词表明写),否则视为隐藏降级

### 5. 链式一致性 `check_chain_consistency`

v1 链式特有:上游结论必须被逐字继承,不能被下游改写。

- M1-M6:输出中若引用 `structure_fingerprint`,必须**逐字**等于 M0 产出
- M7:引用的 `one_leverage`(M1)/ `switch_actions`(M2)/ `environment_checklist`(M3)/ `leverage`(M6)须与上游一致
- 本项需要上游输出,故签名多一个可选参数 `chain_context: dict[str, Any] | None = None`;`runner.py` 传入本盘已完成模块的输出。`chain_context` 为 `None` 时本项跳过(不报错,便于单模块调试)

## 关于误报的立场(实施必读)

**宁可漏报,不可误报**。一个经常喊狼来了的校验器会被无视,那时它的价值是负的。

- 五个校验的模式匹配一律**保守**:证据不足就不判 fail
- 任何一条 failure 必须**自带证据**:命中的原文片段 + 冲突的 ground truth 值,格式如
  `喜忌矛盾:文本"宜多用金"推荐 metal,但后端 unfavorable=['metal','earth'](原文:...)`
  ——没有证据的 failure 无法在 UI 上被人工复核,等于噪声
- 首轮基线(S06)跑完后,**人工复核全部 L2 failure**;发现误报优先收紧模式,而不是留着让人习惯性忽略

## 红线与约束

- **单一事实源**:神煞清单、五行映射各只有一份;禁止在 evalkit 内复制
- **纯函数**:五个校验只读入参,不做 IO、不读环境变量、不调 API——这是它们能被大量单测覆盖的前提
- **宁可漏报**:见上文「关于误报的立场」
- **错误显式传播**:`engine_result` 缺必需键时 raise(说明上游排盘出了问题),不当作"没命中"
- **module-agnostic**:签名与 L2 各项对 module 的适用性由函数内部判断(如格局红线对所有模块适用,链式一致性只对 M1-M7),不在 `runner` 里写 if-else 分支表
- **不碰生产**:只 import `app/`,不改

## 测试

新增 `backend/tests/test_evalkit_grounding.py`,**全部手写正反例,零 API 调用**。每个校验至少一正一反:

| 校验 | 正例 | 反例 |
|---|---|---|
| 喜忌一致性 | 文本推荐 `favorable` 内的五行 | 文本"宜多用金"但后端 `unfavorable` 含 metal |
| 神煞不超界 | 只提本盘命中的神煞 | ① 提"天医"(清单外)② 提"华盖"但本盘未命中 |
| 格局红线 | "命局呈现偏印倾向" | "此为偏印格" |
| special_pattern 诚实 | 特殊盘明说"不入常格扶抑框架" | ① 特殊盘编造"喜用火土" ② 特殊盘只字未提降级 |
| 链式一致性 | M1 引用的 fingerprint 与 M0 逐字相同 | M1 把 fingerprint 改写了一个字 |

额外:
- 普通盘跑 special_pattern 项 → 返回空
- `chain_context=None` → 链式项返回空,不 raise
- `engine_result` 缺 `shensha` 键 → `pytest.raises`
- **误报防御用例**:一段完全合规的长文本跑全部五项 → `failures == []`(防止模式过宽)
